# 管理后台优化与缺陷清单

整理日期：2026-10-21。来源为客户《GFI Admin Portal Feedback》（共 15 页），并结合当前仓库和测试后台只读核对。以下编号用于逐项讨论；复选框仅表示本清单尚未确认完成，不代表所有问题都已在当前版本复现。

复杂度口径：**低**为局部文案或界面调整；**中**需要联动现有接口、数据或多个页面；**高**涉及权限、版本、运营规则、密钥或跨微服务改造。实际工期仍需在确认接口契约和业务规则后评估。

## 工作台（第 2 页）

- [ ] **A-01｜移除资料完整度｜低**：删除 Profile Completion 模块。
- [ ] **A-02｜关键指标可运营｜高**：现有静态数量改为今日收入、新注册、待审核、活跃会员、本月发证等指标，并展示趋势、对比、提醒及点击后的明细入口。需要跨服务统计和历史数据。
- [ ] **A-03｜候选人漏斗｜高**：以 Lead、L0、L1、L2、Chartered 的转化/流失替代技术性的 Stage Distribution，明确各阶段人数及转化口径。
- [ ] **A-04｜业务概览补充运营信息｜中到高**：展示通知投递/死信、会员活跃与到期、证书签发与撤销、收入等；避免重复上方已有指标。

## 用户管理及权限（第 3–5 页）

- [ ] **A-05｜员工和候选人分开管理｜中到高**：把当前混合列表拆为 Internal Staff 与 Students/Candidates；会员是候选人的属性而非独立账号类别，候选人只出现一次。
- [ ] **A-06｜内部员工列表与操作｜高**：列出姓名、邮箱、角色（Ops/Finance/Admin/Super Admin）、状态、MFA、最近登录、创建时间；支持详情、改角色、重置密码、强制登出、重置 MFA、停用/启用及离职。
- [ ] **A-07｜候选人列表与操作｜高**：列出阶段、会员状态、报名数、邮箱验证、最近登录等；支持详情、报名记录、会员管理、重发验证、重置密码、停用/启用和删除。需要状态筛选及行操作/批量操作。
- [ ] **A-08｜五级角色权限矩阵｜高**：Candidate、Ops、Finance、Admin、Super Admin 分别控制查看学生/员工、管理学生/会员/员工、发送消息、删除账号及查看审计日志。授权必须在 BFF/服务端逐接口执行，操作均留审计。目前主要只有基础管理员角色校验。

第 5 页的矩阵将 Finance 标为可“Manage students”，旁边说明却更接近“查看学生、管理支付/会员”；实施 A-08 前需请客户确认 Finance 的实际写权限。

## 课程配置（第 6–7 页）

- [ ] **A-09｜已发布课程允许小修｜高**：草稿自由编辑；已发布课程允许修错字、失效链接、格式等，并让现有学员看到修订。要定义“小修”范围、审计及回滚方式。
- [ ] **A-10｜课程重大变更走新版本｜高**：新增课时、调整测验答案/结构等创建新版本；旧学员保留旧版，新学员进入新版，可选择迁移旧学员；弃用版不再开放新报名但保留已有访问。现有克隆课程不等于报名/进度版本迁移。
- [ ] **A-11｜可视化课程内容工作台｜高**：整合课程→章节→课时编辑，提供目录侧栏、富文本、视频/PDF 嵌入、拖拽排序、实时预览，并覆盖测验和证书相关配置。

## 内容发布与通知（第 8–9 页）

- [ ] **A-12｜Insights/Webinars 后台发布｜高**：后台创建和预览内容、上传文件/视频至 R2、自动建立数据库记录、设置会员等级访问权限及操作审计。客户目前依赖手动上传和 SQL；Webinar 视频托管/权限需确认。
- [ ] **A-13｜通知模板可视化编辑｜中到高**：运营人员可编辑内容、插入变量、校验、多语言预览和测试发送，无须修改 schema/代码才能发布普通文案；新自动触发事件是否仍需开发，应按事件类型单独判断。
- [ ] **A-14｜群发筛选与投递排障｜中到高**：扩展收件人分组；站内信发送前预览；发送记录可查看失败原因和 DLQ。当前已有按证书类别筛选，不应按“完全没有筛选”估算。
- [ ] **A-15｜跨渠道统一通知定义｜高**：邮件和站内信共用一份可版本化、可审计的定义，分别预览各渠道效果，测试后统一发布；需梳理现有两个模板服务的事件/变量契约。

现状：站内信和邮件已有模板管理，邮件已有预览。A-13 至 A-15 的重点是编辑、测试、版本与多渠道发布流程。

## 会员运营与业务配置（第 10–11 页）

- [ ] **A-16｜会员价格与支付映射｜高**：在会员配置中管理价格、币种、Stripe 商品/价格、Xero 映射及税务。商品包已有部分 `pricing_json`/Stripe 信息，但未形成会员方案的完整可视化管理。
- [ ] **A-17｜计费周期与自动续费规则｜高**：配置收费周期、自动续费、宽限期和失败处理，并和真实订阅状态一致。
- [ ] **A-18｜折扣与资格可执行化｜高**：折扣比例、适用商品、Stripe coupon；加入资格由可执行规则判断并关联 CMS，而不只是展示文字。
- [ ] **A-19｜权益继承与方案版本｜高**：定义继承自哪种方案/哪些权益；支持历史版本、对比、恢复、修改人和时间。
- [ ] **A-20｜会员生命周期运营｜高**：到期提醒、取消、过期、升级/降级，以及会员名单、状态筛选、付款失败/重试与订阅 DLQ。
- [ ] **A-21｜人工补偿操作｜高**：补发权益、调整有效期等操作必须限定权限、原因、审批/审计并有可追溯记录。现有后台有 grant/revoke 等接口，但不是完整的运营补偿流程。
- [ ] **A-22｜事件与任务页的配置能力｜高**：客户希望在后台维护价格表、规则引擎、通知模板等，而非仅看运行记录。当前价格与模板分别散在商品包、邮件/站内信页面；需先划定各配置归属，再设计统一入口和服务契约。

现状：会员方案已有增改、弃用/启用，商品包已有价格配置；但会员发布路由对应处理器目前返回 `Not Implemented`，不应把这些现有功能当作零基础，也不能把“可编辑文案”当作完整会员运营能力。

## 证书模板、流水与资格（第 12–14 页）

- [ ] **A-23｜证书模板可视化编辑｜高**：用可编辑字段、图片和变量替代 HTML/Base64 大文本，仍需保持现有模板预览及版本兼容。
- [ ] **A-24｜签名密钥及证书控制权｜高；外部依赖**：客户要求签名私钥由 GFI 控制在其 HSM/KMS，发布信任链，并可独立撤销、重签或补发；还需澄清合同中的知识产权与密钥归属。仓库不足以证明当前私钥实际持有人，需查部署架构、密钥清单和服务合同。
- [ ] **A-25｜证书生成流水可读性｜中**：优先显示证书号、考生姓名及状态；详情显示失败原因、结构化业务字段、本地时区时间，而非主要展示 ULID、哈希和原始 JSON。需要上游提供业务关联字段。
- [ ] **A-26｜流水检索与处理｜中到高**：按状态/时间筛选、搜索、导出、批量操作、失败重试及跳转到考生/证书/验证/订单。当前 PDF 流水路由主要提供列表和详情，重试能力需核对证书任务服务。
- [ ] **A-27｜移除已颁发证书“标记过期”｜低到中；先确认规则**：客户认为已颁发证书不失效。需确认“证书”和其他资格/豁免的生命周期区别，再决定移除或限定该操作。
- [ ] **A-28｜撤销后自动通知｜中**：撤销证书成功后发送站内信和邮件，记录投递结果并避免重复发送。
- [ ] **A-29｜豁免申请与已颁发证书分开｜中**：将申请/豁免资格从证书管理列表中区分，明确两类记录各自可执行的操作及撤回语义。
- [ ] **A-30｜正式恢复资格流程｜高**：撤销不能直接无痕撤回；需要原因、证据、审批、状态迁移、审计及对外验证状态更新。当前页面仅允许对有效资格执行过期/撤销。

证书生成列表的代码已识别待处理、生成中、成功、失败四种状态；测试服当前只有成功样本。A-25、A-26 应先拿到失败样本，再确认缺的是数据、查询接口还是页面展示。

## 审计日志（第 15 页）

- [ ] **A-31｜精简筛选界面｜低**：默认保留关键词搜索，将其余约十项条件收进“高级筛选”，保留已选条件提示和清除能力。
- [ ] **A-32｜服务与动作业务化｜中**：将 `adminbff`、`gcc`、`gcreds`、`gexam`、`glms`、`gmail`、`gpay`、`gprog` 等转换为可理解的业务名称；“动作”选项随服务变化，避免在所有服务下列出全部动作。需核对真实动作字典。
