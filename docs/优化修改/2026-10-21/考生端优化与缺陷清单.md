复杂度口径：**低**为局部文案或界面调整；**中**需要联动现有接口、数据或多个页面；**高**涉及认证、支付、学习规则、数据迁移或跨微服务改造。实际工期仍需在复现问题、确认接口契约和业务规则后评估。

## 注册与登录（第 2–3 页）

- ✅ **C-01｜密码规则｜中；暂缓**：注册密码至少 8 位，同时包含字母和数字。注册入口在 Casdoor；按本次沟通，此项不修改 `candbff`/`candweb`，留待 Casdoor 处理。
- [x] **C-02｜即时验证邮箱验证码｜中到高**：邮箱旁增加“验证验证码”操作，输入后立即反馈结果，不让用户填完其他字段才发现验证码错误。需要核对 Casdoor 注册流程和验证码接口是否支持分步校验。
- [x] **C-03｜注册账号已存在的提示｜中**：客户指出现有英文提示 `Email already exists`；建议替换为原文 `Unable to complete registration. Please sign in or use a different email.` 手机注册同样使用不暴露账号状态的通用提示。由 Casdoor 修改，用户自行搜索替换；服务端响应也应避免暴露账号存在性。
- [ ] **C-04｜手机号所有权验证｜高；待客户提供短信服务**：允许手机登录前，在个人资料中完成“输入手机号 → 发送 OTP → 验证 → 标记为已验证”，登录只认可已验证号码。需客户提供短信供应商/API 文档、可用的测试和正式环境凭证、短信签名与验证码模板及审批状态、发送国家/地区和号码格式、频率/费用限制；还需确认 Casdoor 的手机号验证字段与手机号登录配置。取得资料后再做联调。
- [x] **C-05｜不存在用户的登录提示｜实现低**：客户要求替换为原文 `The user does not exist. Please sign up first.` 由 Casdoor 修改，用户自行搜索替换。该文案会暴露账号是否存在，与 C-03 的安全诉求相反；上线前应让客户确认此取舍。

## 个人资料与账号安全（第 4 页）

- [ ] **C-06｜安全地修改邮箱｜高；代码已改用 Casdoor 验证码，待联调**：安全设置分别向旧邮箱和新邮箱发送 Casdoor 验证码；同一次提交先校验旧邮箱验证码，再由 Casdoor 校验新邮箱验证码并修改账号邮箱。BFF 不再使用 Redis，也不再生成确认链接。部署需确认 Casdoor 考生应用配置了适用于 `reset` 的邮件供应商、组织的 Email 字段允许用户修改；当前请求使用 `captchaType=none`，若 Casdoor 启用 CAPTCHA，需补充相应验证码组件和参数。Casdoor 会按应用配置限制验证码发送频率，连续向两个邮箱发送时可能需等待。完成时会清除当前浏览器的 BFF 登录 cookie；其他设备和 Casdoor SSO 会话失效尚未实现，因此暂不勾选完成。

- ✅ **C-09｜语言偏好｜中；代码已完成**：中文/英文切换写入 Casdoor `Language` 字段，登录后读取并恢复账号偏好；需在测试服验证 Casdoor 字段更新权限。
- ✅ **C-10｜个人链接｜中；代码已完成**：资料页新增 Website、LinkedIn、X 输入和前后端 URL/域名校验，保存后在资料页回显。Website 写入 Casdoor `Homepage`；LinkedIn、X 链接写入 Casdoor `Properties` 的 `gfi_profile_linkedin_url`、`gfi_profile_x_url`。Casdoor 原生 `LinkedIn`、`Twitter` 是社交登录标识，不覆盖。
- [x] **C-11｜营销通知偏好｜高；暂缓**：分别允许订阅或退出“产品发布与公告”“优惠与促销”。Casdoor `Properties` 可以存两类选择，但发送端还需识别营销通知类别、在投递前过滤并记录同意历史；当前未开放偏好入口，避免用户退订后仍收到营销通知。需明确两类通知的发送源、默认订阅状态、必发通知范围和审计要求，再一并实现。
- [ ] **C-12｜账号关闭申请｜高；待业务规则确认**：在应用内提交删除申请，14 天内可撤回；到期执行删除/匿名化并记录审计。Casdoor 有用户禁用/删除能力，但没有覆盖申请、撤销、到期调度和跨订单/证书等服务的数据处理流程；不能仅写一个 Casdoor 自定义字段代替。需先确定订单、证书等依法或业务上必须保留的数据，以及到期后的删除范围。
