# 考生端优化与缺陷清单

整理日期：2026-10-21。来源为客户《GFI Portal Feedback》（截至 10 月 9 日，共 15 页），并结合当前仓库作初步评估。以下编号用于后续逐项讨论；复选框仅表示本清单尚未确认完成，不代表所有问题都已在当前版本复现。

复杂度口径：**低**为局部文案或界面调整；**中**需要联动现有接口、数据或多个页面；**高**涉及认证、支付、学习规则、数据迁移或跨微服务改造。实际工期仍需在复现问题、确认接口契约和业务规则后评估。

## 注册与登录（第 2–3 页）

- [ ] **C-01｜密码规则｜中**：注册密码至少 8 位，同时包含字母和数字。注册入口依赖 Casdoor；需同时核对 Casdoor 的服务端规则、注册页面提示及重置密码规则，避免只做前端校验。
- [ ] **C-02｜即时验证邮箱验证码｜中到高**：邮箱旁增加“验证验证码”操作，输入后立即反馈结果，不让用户填完其他字段才发现验证码错误。需要核对 Casdoor 注册流程和验证码接口是否支持分步校验。
- [ ] **C-03｜注册账号已存在的提示｜中**：客户认为直接显示“邮箱已存在”会暴露账号是否注册；要求改为“无法完成注册，请登录或换用其他邮箱”等通用提示，手机注册同样处理。必须由认证服务统一控制响应，不能仅在页面上替换文字。
- [ ] **C-04｜手机号所有权验证｜高**：允许手机登录前，在个人资料中完成“输入手机号 → 发送 OTP → 验证 → 标记为已验证”。需要保存验证状态，并确保登录流程只认可已验证的号码。
- [ ] **C-05｜不存在用户的登录提示｜待确认；实现低**：客户原文要求提示“用户不存在，请先注册”。这会暴露账号存在性，与 C-03 的诉求冲突；需先确认注册、登录和找回密码是否统一采用不泄露账号状态的提示策略。

## 个人资料与账号安全（第 4 页）

- [ ] **C-06｜安全地修改邮箱｜高**：修改前重新验证身份，向新旧邮箱发送确认链接，双方确认后才更新邮箱，记录审计并强制重新登录。当前通用资料接口已不更新邮箱，需要独立的安全流程。
- [ ] **C-07｜调整资料信息架构｜低**：邮箱和修改密码放在“账号安全”，普通资料页不再显示 Login ID；移除 Display Name、Real Name 的编辑项。先核对姓名在认证、证书及报名中的用途，仅调整展示不能随意删除已有数据。
- [ ] **C-08｜个人头像｜中**：增加可选头像上传、裁剪/预览及保存，供资料和营销展示使用；需要文件存储与读取路径。
- [ ] **C-09｜语言偏好｜中**：保存中文/英文偏好，重新登录后沿用，不再每次重新切换；需确定账号字段及登录后初始化顺序。
- [ ] **C-10｜个人链接｜中**：增加 Website、LinkedIn、X 链接，包含格式校验和展示位置。
- [ ] **C-11｜营销通知偏好｜高**：分别允许订阅或退出“产品发布与公告”“优惠与促销”，并让发送端实际遵守偏好；需要同意记录及审计。
- [ ] **C-12｜账号关闭申请｜高**：在应用内提交删除申请，14 天内可撤回；到期执行删除/匿名化并记录审计。需先确定订单、证书等依法或业务上必须保留的数据。

## 认证邮件（第 5–6 页）

- [ ] **C-13｜注册验证码邮件｜低到中**：按客户第 5 页文案调整问候、六位验证码、10 分钟有效期、安全提醒与 GFI 介绍；需核对实际验证码有效期和邮件模板所在服务。
- [ ] **C-14｜重置密码邮件｜低到中**：按客户第 6 页文案调整；当前邮件同时给验证码和重置链接，客户希望只保留与实际操作一致的一种方式。需先确认重置流程最终采用验证码还是链接。

## 首页与商品目录（第 7–8 页）

- [ ] **C-15｜个性化问候｜低**：首页由“Welcome to Portal”改为“Welcome back, [Name]”，处理没有可用姓名的情况。
- [ ] **C-16｜情境化下一步操作｜中**：根据用户状态展示“Become a Member / Start Your Learning / Explore Options”等可执行入口。
- [ ] **C-17｜重做首页内容｜中到高**：移除库存式统计卡片，改为继续学习及进度、未购课时的开始学习入口、新 Insights 和热门课程。需整合课程进度与内容推荐数据。
- [ ] **C-18｜课程目录分类｜低到中**：将“Learning & Certification Services”改为“Certifications & Courses”；会员方案移至独立 Memberships 入口；移除 All 标签。
- [ ] **C-19｜目录信息与跳转｜中**：认证商品显示 Levels、Modules、Certificates；课程显示 Duration、Level、Units；点击标题进入完整内容页（认证详情按客户要求新标签打开）。需要明确各字段的真实数据来源。
- [ ] **C-20｜价格标签｜低**：固定价格不写“Estimated price”；浮动/起售价使用“From”并明确计算依据。

## 报名、支付与豁免申请（第 9–10 页）

- [ ] **C-21｜报名资料单一来源｜中**：报名页从个人资料预填，原则上只读，并提供“Edit in Profile”入口；需检查未完善资料时如何返回报名流程。
- [ ] **C-22｜出生日期校验｜中**：资料页不允许未来日期，并按最低年龄限制校验。最低年龄数值需要客户确认，前后端均应执行相同规则。
- [ ] **C-23｜条款及隐私政策链接｜低；等待素材**：报名勾选区域链接至正式 CFtP Terms of Service 和 Privacy Policy；客户表示文档后续提供。
- [ ] **C-24｜优惠码导致支付字段消失｜中；先复现**：客户报告输入优惠码后付款字段消失。需按其录屏复现，核对优惠码预览、错误/加载状态及支付组件显示条件，修复后覆盖有效、无效及移除优惠码场景。
- [ ] **C-25｜豁免模板预览/下载报错｜中**：排查附件配置指向的文件是否存在、对象存储键及预览/下载地址；同时明确后台何处上传 Verification Form 模板。
- [ ] **C-26｜申请附件历史｜中到高**：用户可查看历次提交的文件，不仅看到当前申请/最新附件；需确认上游是否保留版本和访问授权。
- [ ] **C-27｜管理员操作时间格式｜低到中**：修复申请详情中 Admin Action At 为 null/unset 时的异常显示，并明确真正缺失时间时的文案；若上游未记录时间则需服务侧修复。

## 课程学习（第 11 页）

- [ ] **C-28｜按真实学习行为记录进度｜高**：减少对“Mark as completed”自报按钮的依赖，依据视频观看、PDF 阅读及测验记录计算完成状态。需先定义每类内容的完成阈值、上报事件、防重复与审计规则。
- [ ] **C-29｜强制前置条件｜高**：必修内容或测验未通过时锁定后续单元、评估/考试，同时显示原因和可前往的操作入口；规则必须在服务端执行，不能只做页面锁态。
- [ ] **C-30｜统一学习旅程界面｜中**：一个持续可见的课程目录/进度面板展示章节、时长、勾选状态和下一步；统一“Learning / Current Stage / Module Progress”等状态文案。当前已有部分进度与锁态数据，可先做展示整合。

## 旧证书验证（第 12 页）

- [ ] **C-31｜旧证书可验证｜高**：客户称旧证书在现有验签页全部失败，并认为旧证书数据迁移属于交付范围。需核实历史证书清单、旧签名密钥/记录和撤销状态，再在迁移旧信任链、重签或可信旧证书核验通道中确定方案；不得把“无新式 PDF 签名”直接判为伪造。
- [ ] **C-32｜简化验证结果｜低到中**：默认展示清晰的“有效/无效”结果与持有人等关键信息，区分“数字签名验证”和“历史记录核验”；七步技术检查折叠到“查看技术详情”，减少 PKI 术语。

## 会员、订单与通知（第 13–15 页）

- [ ] **C-33｜会员页结构及文案｜低到中**：Billing 移至 Purchase History；Current Membership 改为 Your Plan；未入会时给出加入 Affiliate/比较方案入口；方案卡移除 Tier Level，提供 Join Now 和 [Learn more](https://globalfintechinstitute.org/membership/benefits/) 链接。
- [ ] **C-34｜会员决策信息｜中**：每个方案清楚回答“我是否符合资格、现在处于什么状态、下一步是什么”，避免仅展示权益宣传内容；需结合资格及订阅状态。
- [ ] **C-35｜自动续费同意与恢复｜高**：客户报告结账时未同意却默认自动续费，关闭后又无法重新开启。需核对支付/订阅服务的实际默认值、同意记录、取消后的状态机以及重新开启能力，优先修正可能造成非预期扣费的路径。
- [ ] **C-36｜会员流程及配置联测｜高；依赖配置**：客户因缺配置无法测试自动续费、到期提醒、到期通知和会员折扣码。需补测试方案、模板/优惠配置和跨服务联测；不能把“未测”直接判为功能缺失。
- [ ] **C-37｜订单名称与状态｜低到中**：Orders 改为 Purchase History；解释或重命名“Wait Payment”，并区分待支付、支付处理中和支付失败，先核对实际订单状态语义。
- [ ] **C-38｜通知名称与已读数量｜低到中**：Messages 改为 Notifications；修复 Read 标签的数量显示。当前仅有未读总数接口/徽标，已读总数可能需列表统计接口支持。
- [ ] **C-39｜通知时间呈现｜低到中**：7 天内显示“2 小时前/1 天前”，超过 7 天显示绝对时间；审计日志始终显示绝对时间。还需核对服务端时间是否以 UTC 存储，不能仅靠前端格式化掩盖存储问题。
