# 考生系统回归测试任务台账

## 1. 文档用途

本文档是考生系统回归测试任务的统一台账，用于记录：

- 当前有哪些 GitHub Actions 测试任务。
- 每个任务由什么事件驱动。
- 每个任务测试什么、不测试什么。
- 测试使用 Mock 数据还是真实测试环境。
- 新增、修改、删除任务时需要同步维护哪些文件。
- 测试账号、Token、报告和真实数据的安全边界。

GitHub Actions 的实际执行配置以
`.github/workflows/candidate-e2e.yml` 为准。本文档用于解释和维护该配置，
修改工作流时必须同步更新本文档。

当前基线日期：`2026-08-05`。

## 2. 三个任务总览

| 编号 | GitHub Actions Job | 主要测试对象 | 数据来源 | 是否访问真实环境 | 是否允许修改业务数据 |
| --- | --- | --- | --- | --- | --- |
| 任务一 | `Candidate BFF regression` | Go BFF、HTTP 路由、Handler 业务逻辑 | Fake gRPC Client | 否 | 否 |
| 任务二 | `Candidate Playwright regression` | Vue 页面、浏览器交互、Token 和订单体验 | 浏览器 API Mock | 否 | 否 |
| 任务三 | `Candidate live read-only regression` | 真实 Casdoor、真实考生站点、真实 BFF 和微服务 | 测试环境真实数据 | 是 | 否，代码会阻止业务写请求 |

三个任务是三层不同的保护，不互相替代：

- 任务一回答“后端接口代码和业务规则有没有被改坏”。
- 任务二回答“前端页面和用户操作流程有没有被改坏”。
- 任务三回答“部署后的真实测试环境是否真的连得通、登得进、打得开”。

## 3. 驱动方式

统一工作流名称：`Candidate Portal Regression`。

| 驱动事件 | 任务一 | 任务二 | 任务三 |
| --- | --- | --- | --- |
| Push 到 `v2` | 自动执行 | 自动执行 | 跳过 |
| Push 到 `main` | 自动执行 | 自动执行 | 跳过 |
| Pull Request 指向 `v2` | 自动执行 | 自动执行 | 跳过 |
| Pull Request 指向 `main` | 自动执行 | 自动执行 | 跳过 |
| Actions 手动运行，`run_live_readonly=true` | 执行 | 执行 | 执行 |
| Actions 手动运行，`run_live_readonly=false` | 执行 | 执行 | 跳过 |
| 定时任务 | 当前未配置 | 当前未配置 | 当前未配置 |

普通开发流程只需要：

```powershell
git push
```

Push 后，任务一和任务二会自动执行。任务三访问共享测试环境，为避免环境波动
影响每次提交，目前只允许在 GitHub Actions 页面手动执行。

## 4. 任务一：Candidate BFF regression

### 4.1 目标

检查 `candbff` 的编译质量、HTTP 接口合同、鉴权边界和 Handler 业务逻辑。

### 4.2 执行步骤

GitHub Actions 依次执行：

```powershell
go mod download
go vet ./...
go test ./...
go test -count=1 -coverprofile coverage.tmp ./handler ./server
```

当前覆盖率硬门槛为 `20%`。截至 `2026-08-05`，本地最近一次
Handler/Router 合并覆盖率为 `39.9%`。覆盖率会随代码变化，硬门槛以工作流
配置为准。

### 4.3 测试范围

- 健康检查和 JSON 404。
- 98 个 HTTP Method + Route 组合的精确合同。
- 78 个受保护路由的登录鉴权边界。
- CORS 允许和拒绝规则。
- 登录、回调、Cookie、Token 刷新和退出。
- 用户资料输入校验与格式标准化。
- 会员计划、会员记录、账单和取消规则。
- 商城、Pipeline、学习进度和课程报名。
- 资源包、文件归属、预览和查看地址。
- 测验答题、草稿、提交和完成。
- 考试历史、重考、回调和参数校验。
- 资格申请、证书和文件映射。
- 订单筛选、汇总、详情归属和取消状态。
- 发票归属、完成状态、Stripe URL 和 PDF。
- 消息列表、模板渲染、未读、已读和删除。
- 首页统计数据聚合。
- 公共配置不得泄露 Stripe Secret Key。

### 4.4 测试目录

- `candbff/handler/*_test.go`
- `candbff/server/router_test.go`

Handler 测试按业务模块拆分，例如：

- `payment_test.go`
- `invoice_test.go`
- `membership_test.go`
- `message_test.go`
- `certificate_test.go`
- `resource_pack_test.go`
- `quiz_test.go`
- `enrollment_test.go`

测试文件统一放在 `candbff/handler` 和 `candbff/server`，不得散落到其他业务
目录。

### 4.5 使用的数据

Handler 测试使用 Fake gRPC Client，不连接真实 Casdoor、Stripe 或微服务，
不会创建真实订单或修改真实账号。

### 4.6 不覆盖的内容

- 真实 Casdoor 是否在线。
- 测试环境 BFF 是否已经正确部署。
- 微服务、Redis、数据库、NATS 是否真实可用。
- Stripe 和第三方考试供应商是否在线。
- 浏览器页面是否能正常显示。

## 5. 任务二：Candidate Playwright regression

### 5.1 目标

在 Chromium 中自动操作 Vue 考生页面，验证前端状态、按钮、跳转和异常处理。

### 5.2 执行步骤

GitHub Actions 依次执行：

```powershell
npm ci
npm run build
npm run test:e2e:typecheck
npx playwright install --with-deps chromium
npm run test:e2e
```

### 5.3 当前测试范围

当前固定执行 18 条测试：

- 未登录访问受保护页面时保留目标地址并进入登录流程。
- Access Token 过期时只刷新一次，并继续停留在当前页面。
- Refresh Token 也失效时清理本地会话并提示重新登录。
- 订单状态和可执行按钮保持一致。
- 托管支付返回后清理查询参数并同步订单状态。
- 嵌入式支付完成后留在订单页面并刷新订单状态。
- 首页空数据状态和 JavaScript 崩溃检查。
- 商城空数据状态和 JavaScript 崩溃检查。
- 我的认证空数据状态和 JavaScript 崩溃检查。
- 考试空数据状态和 JavaScript 崩溃检查。
- 档案空数据状态和 JavaScript 崩溃检查。
- 资源包空数据状态和 JavaScript 崩溃检查。
- 资格申请空数据状态和 JavaScript 崩溃检查。
- 证书空数据状态和 JavaScript 崩溃检查。
- 会员空数据状态和 JavaScript 崩溃检查。
- 订单空数据状态和 JavaScript 崩溃检查。
- 消息空数据状态和 JavaScript 崩溃检查。
- 设置空数据状态和 JavaScript 崩溃检查。

### 5.4 测试目录

- `candweb/vue-web/e2e/auth.spec.ts`
- `candweb/vue-web/e2e/orders.spec.ts`
- `candweb/vue-web/e2e/portal-smoke.spec.ts`
- `candweb/vue-web/e2e/support/candidate.ts`
- `candweb/vue-web/playwright.config.ts`

### 5.5 使用的数据

测试会在浏览器层拦截 `/api/**` 请求，返回确定的 Mock 数据。Casdoor、Stripe
和后端接口也会被模拟，因此不需要真实账号，不创建真实订单。

### 5.6 失败报告

任务失败时上传：

- `candweb/vue-web/playwright-report/`
- `candweb/vue-web/test-results/`

报告保留 7 天。

### 5.7 不覆盖的内容

- 真实账号密码是否能登录。
- 真实 Cookie、Token 和刷新 Cookie 是否正确下发。
- BFF 和微服务是否已经部署。
- 真实数据库中的订单、证书和消息是否可读取。
- Casdoor、Stripe 或第三方服务的真实可用性。

## 6. 任务三：Candidate live read-only regression

### 6.1 目标

使用真实测试账号登录真实 Casdoor，并访问部署后的考生测试环境，验证真实
站点、BFF 和微服务的只读链路。

### 6.2 驱动方式

任务三只在 GitHub Actions 手动运行时执行：

1. 打开仓库的 `Actions`。
2. 选择 `Candidate Portal Regression`。
3. 点击 `Run workflow`。
4. 选择要测试的分支。
5. 保持 `run_live_readonly` 为勾选状态。
6. 点击绿色的 `Run workflow`。

手动运行时，任务一和任务二也会同时执行。

### 6.3 必需 Secrets

在仓库 `Settings > Secrets and variables > Actions` 中配置：

- `E2E_CANDIDATE_BASE_URL`
- `E2E_CANDIDATE_USERNAME`
- `E2E_CANDIDATE_PASSWORD`

账号密码只能通过 GitHub Secrets 或本地环境变量注入，禁止写入：

- Git 仓库。
- Workflow YAML。
- 测试源码。
- Markdown 文档。
- 测试报告。
- 截图、视频和 Trace。

### 6.4 执行步骤

GitHub Actions 依次执行：

```powershell
npm ci
npm run test:e2e:typecheck
npx playwright install --with-deps chromium
npm run test:e2e:live
```

### 6.5 当前测试范围

当前共识别 14 条测试：

- 1 条真实 Casdoor 登录准备测试。
- 1 条 `/health` 和 `/api/user/me` 真实接口检查。
- 12 条主页面真实数据读取检查。

检查的 12 个页面：

- 首页 `/dashboard`
- 商城 `/certifications`
- 我的认证 `/my-certifications`
- 考试 `/exams`
- 档案 `/records`
- 资源包 `/resource-packs`
- 资格申请 `/credentials`
- 证书 `/certificates`
- 会员 `/membership`
- 订单 `/orders`
- 消息 `/messages`
- 设置 `/settings`

每个页面会检查：

- 登录后没有跳回登录页。
- 页面标题正常显示。
- 页面在 30 秒内完成网络加载。
- 没有意外的 API 4xx 或 5xx。
- 没有 API 请求失败。
- 没有 JavaScript 页面异常。
- 没有业务代码写入 `console.error`。

资源缩略图接口返回 404 属于可选资源缺失，不单独判定整个页面失败。

### 6.6 只读保护

真实只读测试允许：

- `GET`
- `HEAD`
- `OPTIONS`
- `POST /api/auth/refresh`
- `POST /api/telemetry`
- `POST /api/public/telemetry`

其他 `/api/**` 非只读请求会被浏览器测试直接阻止，并将测试判定为失败。

因此当前任务三不会：

- 创建或取消订单。
- 修改个人资料。
- 修改密码或邮箱。
- 标记或删除消息。
- 提交考试、测验或资格申请。
- 发起真实支付。

### 6.7 测试目录

- `candweb/vue-web/e2e-live/auth.setup.ts`
- `candweb/vue-web/e2e-live/read-only.spec.ts`
- `candweb/vue-web/e2e-live/support/live.ts`
- `candweb/vue-web/playwright.live.config.ts`

### 6.8 失败报告和安全

任务失败时只上传：

- `candweb/vue-web/playwright-report-live/`

报告保留 3 天。

真实测试关闭：

- Playwright Trace。
- 自动截图。
- 浏览器视频。

这是为了避免 Cookie、Token、账号信息或真实测试数据进入测试产物。

### 6.9 当前状态

任务三代码和 GitHub Actions Job 已实现。首次真实环境执行需要先配置三个
GitHub Secrets，然后手动运行工作流。未完成首次真实运行前，不能把“真实环境
全绿”视为已经验证。

## 7. 任务和代码改动的对应关系

| 改动类型 | 必须检查或修改的任务 |
| --- | --- |
| 新增、删除、重命名 BFF 路由 | 任务一，更新 `candidateRouteContract` |
| 修改 Handler 参数或响应 | 任务一，增加成功、失败、归属和状态测试 |
| 修复后端业务 Bug | 任务一，增加能复现旧 Bug 的回归测试 |
| 修改登录、Token、订单按钮或支付返回体验 | 任务二 |
| 新增考生主页面 | 任务二和任务三 |
| 修改页面依赖的真实只读接口 | 任务一和任务三 |
| 修改 Casdoor 登录或 Callback | 任务一、任务二和任务三 |
| 新增真实数据写操作回归 | 不得加入任务三，应建立独立的真实业务操作任务 |
| 修改 GitHub Actions 驱动条件 | 更新 Workflow 和本文档的驱动矩阵 |

## 8. 新增任务时的维护规则

新增第四个或后续任务时，必须完成：

1. 明确任务名称和唯一 Job ID。
2. 明确是 Push、Pull Request、手动还是定时驱动。
3. 明确是否访问真实环境。
4. 明确是否会创建或修改业务数据。
5. 明确测试账号和最小权限。
6. 明确测试数据创建与清理方案。
7. 明确失败报告保存哪些文件、保留多少天。
8. 明确哪些 Secrets 或 Variables 是必需的。
9. 将测试代码放入统一目录，不散落到生产代码目录。
10. 更新本文档的任务总览、驱动矩阵、测试范围和变更记录。

如果任务会产生真实订单、支付、考试报名或资格申请，必须使用
`workflow_dispatch` 手动触发，除非已经具备可靠的自动清理机制。

## 9. 修改任务时的维护规则

修改现有任务时，必须同步检查：

- Workflow 中的 Job 名称、`if` 条件和超时时间。
- `package.json` 或 Go 命令。
- Playwright Config、测试目录和报告目录。
- 测试数量和页面清单。
- GitHub Secrets 名称。
- 覆盖率门槛。
- 文档里的驱动矩阵和测试范围。

修改后至少运行对应的本地检查。

任务一相关修改：

```powershell
cd candbff
go vet ./...
go test -count=1 ./...
```

任务二相关修改：

```powershell
cd candweb/vue-web
npm run build
npm run test:e2e:typecheck
npm run test:e2e
```

任务三相关修改：

```powershell
cd candweb/vue-web
npm run test:e2e:typecheck
npm run test:e2e:live -- --list
```

只有在本地安全配置了环境变量，并确认目标是测试环境时，才运行完整的
`npm run test:e2e:live`。

## 10. 删除任务时的维护规则

删除任务时不得只删除 GitHub Actions Job，还必须检查：

1. 删除对应 Workflow Job。
2. 删除不再使用的测试目录和配置文件。
3. 删除不再使用的 `package.json` Script。
4. 删除不再使用的报告目录配置。
5. 确认相关 Secrets 是否可以从 GitHub 删除。
6. 更新本文档的任务总览和驱动矩阵。
7. 更新其他引用该任务的 README 和 Pull Request 模板。
8. 确认删除后仍有其他测试层保护原来的关键风险。

## 11. 当前未覆盖的后续任务

以下内容不属于当前三个任务：

- 真实环境创建并取消未支付订单。
- Stripe 测试模式真实支付。
- 真实考试报名、改期、取消和重考。
- 真实资格申请、文件上传和重新提交。
- 真实课程学习、测验提交和进度同步。
- 已支付订单的 Admin 清理或退款。
- 页面加载性能指标和大 Chunk 性能门槛。

这些操作会修改真实测试数据，应作为独立的“真实业务操作回归任务”设计，
并先确定测试账号、清理方式和失败恢复方案。
