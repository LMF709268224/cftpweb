# 管理系统回归测试任务台账

## 1. 文档用途

本文档记录管理系统自动回归任务的驱动方式、测试边界、维护规则和安全要求。
GitHub Actions 的实际配置以 `.github/workflows/admin-e2e.yml` 为准，修改工作流时
必须同步更新本文档。

当前基线日期：`2026-08-11`。

## 2. 三个任务总览

| 编号 | GitHub Actions Job | 主要测试对象 | 数据来源 | 真实环境 | 修改业务数据 |
| --- | --- | --- | --- | --- | --- |
| 任务一 | `Admin BFF regression` | Go BFF、路由合同、鉴权边界 | 测试夹具 | 否 | 否 |
| 任务二 | `Admin Playwright regression` | Vue 页面、登录状态和消息红点 | 浏览器 API Mock | 否 | 否 |
| 任务三 | `Admin live regression` | 真实 Casdoor、站点、BFF 和微服务只读接口 | 测试环境真实数据 | 是 | 否 |

三个任务分别保护后端 HTTP 合同、浏览器页面行为和部署环境连通性，不能互相替代。
管理操作通常具有审批、发布、重试、作废或清理等副作用。在明确测试数据和回滚
合同前，任务三只允许只读检查，不提供真实环境写入开关。

### 2.1 各层测试怎样才算通过

| 测试层 | 是否像用户一样使用 Web | 当前通过标准 | 不能证明的内容 |
| --- | --- | --- | --- |
| BFF regression | 否，直接调用 Go Handler 或 Router | 路由、鉴权、请求参数、gRPC 调用和响应字段符合测试合同 | 浏览器页面、真实部署和真实微服务可用性 |
| Playwright regression | 是，Chromium 打开真实 Vue 页面并点击界面；但登录状态和 API 数据是 Mock | 22 个冒烟用例要求路由、首要 API、标题和无页面异常；专项用例还要求固定 Mock 数据的关键字段正确展示、交互符合预期且不发业务写请求 | 真实账号登录、真实 BFF/微服务、真实数据库数据 |
| Live regression | 是，使用真实测试账号登录部署后的 Web | 能进入正确 URL，页面标题可见，API 无 `4xx/5xx` 或请求失败，页面无异常和 `console.error`，且没有业务写请求 | 当前不要求列表非空，不逐字段核对真实业务数据，也不打开每个详情验证内容 |

因此，只有“打开页面并正常显示”代表该页面通过了冒烟或真实只读连通性检查，
不代表该模块所有字段、筛选、分页、详情和业务规则都已通过。只有下文明确列出的
专项用例，才校验对应 Mock 数据的展示或具体交互。

## 3. 驱动方式

统一工作流名称：`Admin Portal Regression`。

| 驱动事件 | 任务一 | 任务二 | 任务三 |
| --- | --- | --- | --- |
| Push 到 `v2` 或 `main` | 自动执行 | 自动执行 | 跳过 |
| Pull Request 指向 `v2` 或 `main` | 自动执行 | 自动执行 | 跳过 |
| Actions 手动运行，`run_live_readonly=true` | 执行 | 执行 | 执行 |
| Actions 手动运行，`run_live_readonly=false` | 执行 | 执行 | 跳过 |
| 定时任务 | 未配置 | 未配置 | 未配置 |

真实环境测试必须手动运行，避免共享环境波动阻塞普通提交，也避免在未知目标环境
上自动使用管理账号。

## 4. 任务一：Admin BFF regression

### 4.1 执行步骤

```powershell
cd adminbff
go mod download
go vet ./...
go test ./...
go test -count=1 -cover ./handler
```

### 4.2 当前范围

- 健康检查返回和 JSON 404。
- `276` 个 HTTP Method + Route 组合的精确指纹，防止路由被意外删除或改名。
- 除健康检查和四个登录接口外，所有管理接口必须经过登录鉴权。
- 登录 URL 与 OAuth State 绑定，State 随机、一次性、支持并发登录且限制待处理数量；
  回调校验通过后不向浏览器泄露 Token。
- 大 Token Cookie 分片、旧版 Cookie 兼容、缺片和畸形 Cookie 拒绝、缺少 Refresh
  Cookie 的未授权响应。
- CORS 允许来源和未知来源边界。
- 消息和邮件红点分别计数，下游失败不会伪装成正常结果。
- 资格申请列表的状态筛选、分页结果和申请详情只读合同。
- 资格定义列表与详情的只读合同。
- 订单列表的筛选、分页、规范化结果和业务详情只读合同。
- 管理员已发送消息列表的状态筛选、分页结果和数量只读合同。
- 发票列表的分页、金额换算、状态和时间字段规范化只读合同。
- PDF 生成请求列表、分页和详情字段的只读合同。
- 审计日志列表筛选、分页和 Layer 2 详情的只读合同。
- Webhook 列表状态筛选、分页和 Payload 详情的只读合同；不调用重放接口。
- 考试列表筛选、分页、详情、成绩详情和状态流转记录的只读合同；不调用同步接口。
- PDF 模板列表及模板内容、字段定义合并详情的只读合同。
- 消息模板列表筛选、分页、数量及模板详情的只读合同。
- 资源包列表状态筛选、计数、游标分页和资源包详情的只读合同。
- 资源文件按资源包筛选、计数、游标分页和文件详情的只读合同。
- LMS 课程列表状态映射、游标分页、课程详情和完整课程树的只读合同。
- 管线列表状态映射、分类筛选、当前版本筛选、游标分页和管线详情的只读合同。
- 商品套餐列表状态筛选、当前版本筛选、计数、游标分页和套餐详情的只读合同。
- 会员配置列表游标分页和会员配置详情的只读合同。
- 工作台用户筛选、用户分页、考生标识、认证阶段和当日已支付订单聚合的只读合同。
- 支付订阅的客户、状态、游标、页大小和排序参数，以及分页响应的只读合同。
- 运维任务其余支付、商城邮件/NATS、会员邮件、认证邮件/阶段/课程单元/驱动事件/NATS、
  考试审计/状态流转/提醒邮件列表的全部筛选和分页参数，以及详情/摘要路径 ID 合同。
- 上述 `24` 个运维列表和详情入口的下游不可用错误映射，不把 gRPC `Unavailable`
  伪装成成功响应。
- 考生资格查询目标、缺少必填参数和查询结果的只读合同。
- 当前管理员完整个人资料读取合同。
- GCC Catalog 合同缺失时明确返回不可用，不伪造接口结果。
- 请求体大小限制，以及商品展示价格同步接口的畸形/空请求体边界；测试使用 Fake
  Client，不连接真实服务或修改真实数据。
- gRPC 传输凭证配置和仓库现有 Handler、工具、服务层单元测试。

测试入口为 `adminbff/server/router_test.go` 及各包的 `*_test.go`。当前 Handler
覆盖率硬门槛为 `22.0%`，截至 `2026-08-11` 本地测得 `23.9%`。新增或修复管理端
Handler 时必须增加针对性单元测试，并随覆盖提高逐步上调工作流门槛。

## 5. 任务二：Admin Playwright regression

### 5.1 执行步骤

```powershell
cd adminweb/vue-web
npm ci
npm run build
npm run test:e2e:typecheck
npx playwright install chromium
npm run test:e2e
```

### 5.2 当前范围

当前固定执行 `89` 条 Chromium 测试：

- `22` 个管理页面的路由、标题、首要 API 请求和 JavaScript 异常冒烟检查。
- 未登录进入受保护页面时保留完整目标地址。
- Access Token 失效时只刷新一次，然后重试原请求。
- Refresh Token 失效时清理浏览器会话，并保留原工作台返回地址。
- 消息与站内信红点分别显示各自未读数，防止状态串用。
- 资格申请列表正确展示申请人、资格、状态和申请 ID。
- 资格申请详情正确展示元数据和证明文件，且只发送 GET 请求。
- 资格定义列表与详情正确展示分类、资源路径和文件约束，且只发送 GET 请求。
- 订单列表与详情正确展示金额、状态和业务元数据，且只发送 GET 请求。
- 发票列表和详情正确展示订单、金额、状态与支付时间，且只发送 GET 请求。
- PDF 生成请求列表和详情正确展示任务状态、资格定义及文件校验值，且只发送 GET 请求。
- 审计日志列表和详情正确展示操作摘要与 Layer 2 字段，且只发送 GET 请求。
- Webhook 列表和详情正确展示处理结果与 Payload 元数据，且不触发重放并只发送 GET 请求。
- 考试列表、详情、成绩和状态流转记录正确展示，且不触发同步并只发送 GET 请求。
- Prog 认证实例列表、阶段、课程单元和状态日志详情正确展示，且不触发人工推进并只发送 GET 请求。
- 消息模板、已发送消息列表和详情正确展示，且不编辑模板、不发送消息并只发送 GET 请求。
- 邮件模板、已发送邮件和投递状态详情正确展示，且不编辑模板、不取消邮件并只发送 GET 请求。
- PDF 模板列表、HTML 内容和字段定义详情正确展示，且不编辑模板并只发送 GET 请求。
- 资源包列表和详情正确展示状态、路径及封面信息，且不发布、不下架、不编辑并只发送 GET 请求。
- 资源文件列表和详情正确展示所属资源包、文件类型、对象 Key 及校验值，且不上传、不编辑、不删除并只发送 GET 请求。
- LMS 课程列表和详情正确展示发布状态、章节、课时、测验和资料数量，且不发布、不导入、不编辑并只发送 GET 请求。
- 管线列表和详情正确展示分类、状态、版本及配置标识，且不发布、不废弃、不删除、不编辑并只发送 GET 请求。
- 商品套餐列表和详情正确展示价格、状态、版本、描述及关联项，且不发布、不废弃、不同步价格、不删除、不编辑并只发送 GET 请求。
- 会员配置列表和详情正确展示期限、等级、角色及适用对象，且不废弃、不编辑并只发送 GET 请求。
- 工作台正确展示非空用户、汇总和分页信息；快速变更筛选时，较早的慢响应不能覆盖最后一次结果；首次读取失败后可刷新恢复，且只发送 GET 请求。
- 运维任务覆盖支付订阅、支付 Webhook、支付订单项、商城/会员/认证邮件任务、商城/认证 NATS、认证阶段/课程单元/驱动事件、考试审计/状态流转/提醒邮件全部 `14` 个子模块的非空列表；覆盖支付订阅筛选、游标下一页和返回上一页，并打开 `11` 个可用详情；另覆盖列表失败重试、详情失败后重新打开、切换模块时忽略旧慢响应，且只发送 GET 请求。
- 权限页正确展示资格定义和考生资格查询结果；查询期间切换考生时忽略旧结果；资格定义首次读取失败后可刷新恢复，且不执行授予、撤销、过期或作废操作并只发送 GET 请求。
- 设置页正确展示管理员完整资料，首次读取失败后可重新加载成功，且不保存资料、不修改密码并只发送 GET 请求。

页面覆盖：首页、资源包、资源文件、学习管理、管线、商品、会员、项目、考试、
消息、站内信、订单、发票、证书、资格申请、PDF 模板、PDF 请求、运维任务、审计
日志、Webhook、权限和设置。

上文所有 `22` 个页面目前都同时具有空数据冒烟和至少一项固定 Mock 数据专项断言。
运维任务的全部子模块均有非空列表断言；有详情接口的子模块还会打开详情。冒烟
测试本身仍使用空数据响应，因此它只证明空状态可显示，不能替代专项断言。

测试文件位于 `adminweb/vue-web/e2e/`，浏览器层统一 Mock `/api/**`，不需要真实
账号，也不会访问或修改真实业务数据。失败时上传 `playwright-report/` 和
`test-results/`，保留 7 天。

## 6. 任务三：Admin live regression

### 6.1 运行方式

在 GitHub Actions 中选择 `Admin Portal Regression`，手动运行并保持
`run_live_readonly=true`。任务需要以下 Repository Secrets：

- `E2E_ADMIN_BASE_URL`
- `E2E_ADMIN_USERNAME`
- `E2E_ADMIN_PASSWORD`

账号应是专用测试管理账号，并仅授予覆盖页面所需的最小只读权限。目标地址必须是
测试环境，不得配置生产环境。

### 6.2 当前范围和安全边界

- 通过真实 BFF 获取 Casdoor 登录地址并完成登录。
- 校验健康检查和当前管理员接口。
- 依次打开任务二覆盖的 `22` 个管理页面，等待其 API 请求完成。
- 失败条件包括 HTTP `4xx/5xx`、请求失败、页面异常和 `console.error`。
- Playwright 网络层会在请求离开浏览器前阻断除 `/api/auth/refresh` 外所有非
  `GET`、`HEAD`、`OPTIONS` 管理 API 请求；令牌刷新只更新认证会话，不修改业务
  数据。一旦页面尝试业务写操作，测试立即失败。
- 线上报告关闭截图、录像和 Trace，避免管理数据或登录信息进入构建产物。
- 当前只读阶段不要求测试账号预置每个模块的数据，也不校验列表非空、具体字段值、
  筛选、分页或详情弹层；这些属于后续真实数据断言任务。

测试文件位于 `adminweb/vue-web/e2e-live/`。失败时只上传净化后的 HTML 报告，
保留 3 天。登录状态文件位于 `test-results/live-auth/`，被 Git 忽略且不上传。

本地仅检查用例发现时可执行：

```powershell
cd adminweb/vue-web
npm run test:e2e:typecheck
npm run test:e2e:live -- --list
```

只有在安全配置三个环境变量并确认目标为测试环境后，才运行完整线上测试。

## 7. 代码改动对应关系

| 改动类型 | 必须检查或修改的任务 |
| --- | --- |
| 新增、删除、重命名 BFF 路由 | 任务一，更新路由数量和指纹 |
| 修改 Handler 参数、响应或权限 | 任务一，增加成功、失败和鉴权测试 |
| 修复后端业务 Bug | 任务一，增加能复现旧 Bug 的回归测试 |
| 新增或重命名管理页面 | 任务二和任务三，更新页面清单 |
| 修改登录、Token 刷新或路由守卫 | 任务一、任务二和任务三 |
| 修改消息或站内信未读状态 | 任务一和任务二 |
| 修改页面依赖的真实只读接口 | 任务一和任务三 |
| 新增真实环境写操作 | 不得加入只读任务；先明确专用数据、最小权限和回滚合同 |
| 修改 GitHub Actions 驱动条件 | 同步更新工作流和本文档 |

## 8. 维护规则

新增或修改测试任务时必须同步确认：任务名称和触发条件、数据来源、账号权限、
是否写数据、清理方式、Secrets、报告内容和保留时间。测试代码应放在现有 BFF
测试包、`e2e/` 或 `e2e-live/`，不得散落进生产代码。

删除任务时必须同时删除不再使用的 Workflow Job、测试目录、配置、npm Script、
报告路径和文档记录，并确认原风险仍有其他测试层保护。

## 9. 当前未覆盖

- Admin BFF 的运维只读列表/详情成功和下游不可用分支已覆盖；其他模块仍有部分
  Handler 缺少完整失败分支，当前 Handler 覆盖率实测 `23.9%`，硬门槛为 `22.0%`。
- 除已覆盖的工作台、运维任务、权限和设置错误恢复/竞态/分页边界外，其余专项页面
  的失败提示、重试、快速切换筛选竞态、前后分页和空数据/接口错误区分仍未系统补齐。
- 运维任务的 BFF 已覆盖各列表筛选参数和下游不可用映射，但浏览器层除支付订阅外，
  尚未逐一操作每个可选筛选条件，也未穷举所有状态枚举和空游标边界。
- 真实环境的非空数据和关键字段展示、筛选、分页、详情弹层断言；当前 Live 任务只
  做登录、页面标题、API 和浏览器异常检查。
- `BUG-ADMIN-AUTH-001`：同一账号首次登录显示“认证失败”、第二次成功。等待取得
  首次 `/api/auth/login` 的 HTTP 状态、`error_code` 和 BFF 日志后修复，并补首次
  登录成功及失败后重试回归；详细记录见 `ztest/可推进工作项清单.md`。
- 真实环境审批、发布、重试、取消、作废、删除、同步和清理操作。
- 文件上传、实际 PDF 生成、Webhook 重放等会产生外部副作用的流程；当前只覆盖 PDF
  请求和 Webhook 记录的查看。
- 不同管理角色的页面和接口权限矩阵。
- 移动端关键页面、键盘操作和可访问性专项回归。
- 页面性能和大 Chunk 门槛。

这些能力进入自动回归前，必须先确定服务合同、专用测试数据和失败后的恢复方式。
