# 管理系统回归测试任务台账

## 1. 文档用途

本文档记录管理系统自动回归任务的驱动方式、测试边界、维护规则和安全要求。
GitHub Actions 的实际配置以 `.github/workflows/admin-e2e.yml` 为准，修改工作流时
必须同步更新本文档。

当前基线日期：`2026-08-11`。

## 2. 三个任务总览

| 编号 | GitHub Actions Job | 主要测试对象 | 数据来源 | 真实环境 | 修改业务数据 |
| --- | --- | --- | --- | --- | --- |
| 任务一 | `Admin BFF regression` | Go BFF、路由合同、鉴权边界 | 测试夹具 | 否 | 否 |
| 任务二 | `Admin Playwright regression` | Vue 页面、登录状态和消息红点 | 浏览器 API Mock | 否 | 否 |
| 任务三 | `Admin live regression` | 真实 Casdoor、站点、BFF 和微服务只读接口 | 测试环境真实数据 | 是 | 否 |

三个任务分别保护后端 HTTP 合同、浏览器页面行为和部署环境连通性，不能互相替代。
管理操作通常具有审批、发布、重试、作废或清理等副作用。在明确测试数据和回滚
合同前，任务三只允许只读检查，不提供真实环境写入开关。

## 3. 驱动方式

统一工作流名称：`Admin Portal Regression`。

| 驱动事件 | 任务一 | 任务二 | 任务三 |
| --- | --- | --- | --- |
| Push 到 `v2` 或 `main` | 自动执行 | 自动执行 | 跳过 |
| Pull Request 指向 `v2` 或 `main` | 自动执行 | 自动执行 | 跳过 |
| Actions 手动运行，`run_live_readonly=true` | 执行 | 执行 | 执行 |
| Actions 手动运行，`run_live_readonly=false` | 执行 | 执行 | 跳过 |
| 定时任务 | 未配置 | 未配置 | 未配置 |

真实环境测试必须手动运行，避免共享环境波动阻塞普通提交，也避免在未知目标环境
上自动使用管理账号。

## 4. 任务一：Admin BFF regression

### 4.1 执行步骤

```powershell
cd adminbff
go mod download
go vet ./...
go test ./...
go test -count=1 -cover ./handler
```

### 4.2 当前范围

- 健康检查返回和 JSON 404。
- `276` 个 HTTP Method + Route 组合的精确指纹，防止路由被意外删除或改名。
- 除健康检查和四个登录接口外，所有管理接口必须经过登录鉴权。
- 畸形登录 Cookie 被拒绝。
- CORS 允许来源和未知来源边界。
- 资格申请列表的状态筛选、分页结果和申请详情只读合同。
- 资格定义列表与详情的只读合同。
- 订单列表的筛选、分页、规范化结果和业务详情只读合同。
- 管理员已发送消息列表的状态筛选、分页结果和数量只读合同。
- 发票列表的分页、金额换算、状态和时间字段规范化只读合同。
- PDF 生成请求列表、分页和详情字段的只读合同。
- 审计日志列表筛选、分页和 Layer 2 详情的只读合同。
- Webhook 列表状态筛选、分页和 Payload 详情的只读合同；不调用重放接口。
- 仓库现有 Handler、工具和服务层单元测试。

测试入口为 `adminbff/server/router_test.go` 及各包的 `*_test.go`。当前 Handler
覆盖率硬门槛为 `9.0%`，截至 `2026-08-11` 本地测得 `9.4%`。新增或修复管理端
Handler 时必须增加针对性单元测试，并随覆盖提高逐步上调工作流门槛。

## 5. 任务二：Admin Playwright regression

### 5.1 执行步骤

```powershell
cd adminweb/vue-web
npm ci
npm run build
npm run test:e2e:typecheck
npx playwright install chromium
npm run test:e2e
```

### 5.2 当前范围

当前固定执行 `40` 条 Chromium 测试：

- `22` 个管理页面的路由、标题、首要 API 请求和 JavaScript 异常冒烟检查。
- 未登录进入受保护页面时保留完整目标地址。
- Access Token 失效时只刷新一次，然后重试原请求。
- Refresh Token 失效时清理浏览器会话，并保留原工作台返回地址。
- 消息与站内信红点分别显示各自未读数，防止状态串用。
- 资格申请列表正确展示申请人、资格、状态和申请 ID。
- 资格申请详情正确展示元数据和证明文件，且只发送 GET 请求。
- 资格定义列表与详情正确展示分类、资源路径和文件约束，且只发送 GET 请求。
- 订单列表与详情正确展示金额、状态和业务元数据，且只发送 GET 请求。
- 发票列表和详情正确展示订单、金额、状态与支付时间，且只发送 GET 请求。
- PDF 生成请求列表和详情正确展示任务状态、资格定义及文件校验值，且只发送 GET 请求。
- 审计日志列表和详情正确展示操作摘要与 Layer 2 字段，且只发送 GET 请求。
- Webhook 列表和详情正确展示处理结果与 Payload 元数据，且不触发重放并只发送 GET 请求。

页面覆盖：首页、资源包、资源文件、学习管理、管线、商品、会员、项目、考试、
消息、站内信、订单、发票、证书、资格申请、PDF 模板、PDF 请求、运维任务、审计
日志、Webhook、权限和设置。

测试文件位于 `adminweb/vue-web/e2e/`，浏览器层统一 Mock `/api/**`，不需要真实
账号，也不会访问或修改真实业务数据。失败时上传 `playwright-report/` 和
`test-results/`，保留 7 天。

## 6. 任务三：Admin live regression

### 6.1 运行方式

在 GitHub Actions 中选择 `Admin Portal Regression`，手动运行并保持
`run_live_readonly=true`。任务需要以下 Repository Secrets：

- `E2E_ADMIN_BASE_URL`
- `E2E_ADMIN_USERNAME`
- `E2E_ADMIN_PASSWORD`

账号应是专用测试管理账号，并仅授予覆盖页面所需的最小只读权限。目标地址必须是
测试环境，不得配置生产环境。

### 6.2 当前范围和安全边界

- 通过真实 BFF 获取 Casdoor 登录地址并完成登录。
- 校验健康检查和当前管理员接口。
- 依次打开任务二覆盖的 `22` 个管理页面，等待其 API 请求完成。
- 失败条件包括 HTTP `4xx/5xx`、请求失败、页面异常和 `console.error`。
- Playwright 网络层会在请求离开浏览器前阻断除 `/api/auth/refresh` 外所有非
  `GET`、`HEAD`、`OPTIONS` 管理 API 请求；令牌刷新只更新认证会话，不修改业务
  数据。一旦页面尝试业务写操作，测试立即失败。
- 线上报告关闭截图、录像和 Trace，避免管理数据或登录信息进入构建产物。

测试文件位于 `adminweb/vue-web/e2e-live/`。失败时只上传净化后的 HTML 报告，
保留 3 天。登录状态文件位于 `test-results/live-auth/`，被 Git 忽略且不上传。

本地仅检查用例发现时可执行：

```powershell
cd adminweb/vue-web
npm run test:e2e:typecheck
npm run test:e2e:live -- --list
```

只有在安全配置三个环境变量并确认目标为测试环境后，才运行完整线上测试。

## 7. 代码改动对应关系

| 改动类型 | 必须检查或修改的任务 |
| --- | --- |
| 新增、删除、重命名 BFF 路由 | 任务一，更新路由数量和指纹 |
| 修改 Handler 参数、响应或权限 | 任务一，增加成功、失败和鉴权测试 |
| 修复后端业务 Bug | 任务一，增加能复现旧 Bug 的回归测试 |
| 新增或重命名管理页面 | 任务二和任务三，更新页面清单 |
| 修改登录、Token 刷新或路由守卫 | 任务一、任务二和任务三 |
| 修改消息或站内信未读状态 | 任务一和任务二 |
| 修改页面依赖的真实只读接口 | 任务一和任务三 |
| 新增真实环境写操作 | 不得加入只读任务；先明确专用数据、最小权限和回滚合同 |
| 修改 GitHub Actions 驱动条件 | 同步更新工作流和本文档 |

## 8. 维护规则

新增或修改测试任务时必须同步确认：任务名称和触发条件、数据来源、账号权限、
是否写数据、清理方式、Secrets、报告内容和保留时间。测试代码应放在现有 BFF
测试包、`e2e/` 或 `e2e-live/`，不得散落进生产代码。

删除任务时必须同时删除不再使用的 Workflow Job、测试目录、配置、npm Script、
报告路径和文档记录，并确认原风险仍有其他测试层保护。

## 9. 当前未覆盖

- 管理端多数 Handler 的业务分支；当前覆盖率门槛仍较低。
- 真实环境审批、发布、重试、取消、作废、删除、同步和清理操作。
- 文件上传、实际 PDF 生成、Webhook 重放等会产生外部副作用的流程；当前只覆盖 PDF
  请求和 Webhook 记录的查看。
- 不同管理角色的页面和接口权限矩阵。
- 页面性能和大 Chunk 门槛。

这些能力进入自动回归前，必须先确定服务合同、专用测试数据和失败后的恢复方式。
