# CFTP 正式环境部署清单

## 1. 客户需要提供的内容

### 1.1 服务器

推荐使用“2 台应用服务器 + 托管 PostgreSQL + 托管 Redis + 对象存储”的部署方式。

| 数量 | 配置要求 | 用途 | 客户需提供 |
| --- | --- | --- | --- |
| 2 台 | 每台至少 8 vCPU、32 GB 内存、300 GB SSD/NVMe；Ubuntu Server 22.04/24.04 LTS；内网互通 | 组成 K3s 集群，部署全部 Web、BFF、认证、配置中心、业务微服务、NATS 和日志组件 | 内网 IP、主机名、SSH 端口、运维账号、sudo 权限、登录方式 |

服务器还需要满足：

- 可以访问镜像仓库、PostgreSQL、Redis、对象存储、SMTP、Stripe 和考试系统；
- 配置固定内网 IP、DNS 和 NTP 时间同步；
- 客户完成安全组、防火墙、VPN 或堡垒机放行；
- 如需要严格的 Kubernetes 控制面高可用，应增加至 3 台应用服务器。

### 1.2 域名和公网证书

| 数量 | 内容 | 用途 |
| --- | --- | --- |
| 3 个域名 | 考生端域名，如 `candidate.example.com` | 考生访问系统 |
|  | 管理端域名，如 `admin.example.com` | 管理员访问系统 |
|  | Casdoor 域名，如 `auth.example.com` | 登录和统一认证 |
| 1 张或 3 张证书 | 推荐提供 1 张覆盖以上 3 个域名的 `*.example.com` 通配符证书或 SAN 多域名证书；也可以分别提供 3 张证书 | HTTPS 访问 |

客户需同时提供：

- TLS 证书、私钥和完整证书链；
- DNS 解析操作权限，或负责添加 A/CNAME/TXT 记录的联系人；
- 公网负载均衡、WAF、备案和管理端 IP 白名单要求（如有）；
- Stripe 和考试系统需要的公网回调域名可以复用考生端域名，不要求额外证书。

### 1.3 PostgreSQL

| 数量 | 建议规格 | 用途 |
| --- | --- | --- |
| 1 套高可用实例 | PostgreSQL 14+；4～8 vCPU；16～32 GB 内存；500 GB SSD 起；启用自动备份 | 保存各微服务业务数据和 Casdoor 数据 |

客户需提供：

- 主机、端口、TLS 连接要求和网络白名单；
- 建库/建 Schema、建表和初始化数据的部署账号；
- 应用运行账号；
- 数据库命名规范；
- 自动备份周期、保留时间及恢复方式。

各服务使用独立 Database 还是独立 Schema，以本次后台发布包中的连接配置和 SQL 脚本为准。

### 1.4 Redis

| 数量 | 建议规格 | 用途 |
| --- | --- | --- |
| 1 套高可用实例 | Redis 6.0+；2～4 vCPU；8～16 GB 内存 | 缓存、会话和分布式锁 |

客户需提供：

- 访问地址、端口、账号、密码和 TLS 要求；
- 网络白名单；
- 实例模式、最大连接数、持久化和备份策略。

### 1.5 对象存储

| 数量 | 建议规格 | 用途 |
| --- | --- | --- |
| 1 套 | S3/OSS 等托管对象存储，容量 1 TB 起；私有化环境可提供高可用 MinIO | 存储课程资料、视频、图片、商品封面和 PDF 文件 |

客户需提供：

- Endpoint、Region 和 Bucket 名称；
- Access Key、Secret Key，或等效授权方式；
- 内网/公网访问地址；
- CORS、文件大小、生命周期和备份要求；
- CDN 域名和配置（如使用）。

如果客户不提供对象存储，我方需要额外部署 MinIO，并需要客户提供独立持久化磁盘和备份位置。

### 1.6 邮件服务

| 数量 | 用途 | 客户需提供 |
| --- | --- | --- |
| 1 个 SMTP/邮件服务账号 | 发送注册、订单、支付、考试、证书和会员通知邮件 | SMTP 主机、端口、SSL/TLS 方式、账号、密码/令牌、发件人名称、发件人邮箱 |

客户还需完成发信域名的 SPF、DKIM、DMARC 配置，并提供测试收件邮箱。

### 1.7 支付和考试系统

| 系统 | 用途 | 客户需提供 |
| --- | --- | --- |
| Stripe 正式商户 | 商品、课程、会员等在线支付 | Publishable Key、Secret Key、Webhook Secret、结算币种、商户账号联系人 |
| Prometric/GEE | 考试预约、考试代码及成绩回传 | 正式接口地址、账号/密钥、接口文档、网络白名单、回调要求、联调联系人 |

不启用其中某项时，客户需要明确确认相应业务功能暂不上线。

### 1.8 镜像、密钥和运维信息

客户需提供：

- 私有容器镜像仓库地址、项目名称及推送/拉取账号；
- 生产密钥的保管方式，如 Kubernetes Secret、KMS 或 OpenBao；
- 日志保留周期和备份保留周期；
- Grafana/企业微信告警接收人及企业微信机器人 Webhook；
- 发布窗口、客户运维联系人和故障联系人。

## 2. 我方需要完成的部署工作

### 2.1 部署位置

| 位置 | 部署内容 |
| --- | --- |
| 2 台应用服务器组成的 K3s 集群 | Traefik/Ingress、Casdoor、`cfgserver`、Web、BFF、全部 Go 微服务、NATS JetStream、Vector、Loki、Grafana |
| 客户 PostgreSQL | 各微服务数据库/Schema、Casdoor 数据库 |
| 客户 Redis | 缓存、会话和分布式锁数据 |
| 客户对象存储 | 课程、视频、图片、封面和 PDF 文件 |
| 客户 SMTP、Stripe、Prometric/GEE | 由集群内对应服务通过正式接口连接，不在本地部署 |

关键无状态服务在两台应用服务器上各部署 1 个副本。NATS、Loki 等有状态组件必须配置 PVC；如果客户已有对应平台，则改为接入客户平台。

### 2.2 集群和基础组件

| 服务 | 部署位置 | 需要完成的配置 |
| --- | --- | --- |
| K3s | 2 台应用服务器 | 集群节点、命名空间、StorageClass、镜像拉取 Secret、节点调度 |
| Traefik/Ingress | K3s | 3 个域名、HTTPS 证书、Web/BFF/Casdoor 路由、回调路径 |
| NATS JetStream | K3s | 集群地址、认证、JetStream、PVC、消息保留策略 |
| Vector | 每台应用服务器 | 采集容器日志并发送到 Loki |
| Loki | K3s | PVC、日志保留时间、容量限制 |
| Grafana | K3s | Loki 数据源、管理员密码、看板、企业微信告警 |
| MinIO（仅客户未提供对象存储时） | K3s 或独立存储服务器 | Endpoint、Bucket、账号、PVC、备份 |

### 2.3 认证和配置中心

| 服务 | 部署位置 | 需要完成的配置 |
| --- | --- | --- |
| Casdoor | K3s | PostgreSQL、外部域名、TLS、CFTP 组织、管理端应用、考生端应用、回调地址、初始管理员、角色和权限 |
| `cfgserver` | K3s | PostgreSQL、Redis、NATS、对象存储、服务地址、服务间 TLS、SMTP、Stripe、Prometric/GEE 等运行配置 |

### 2.4 Web 和 BFF 服务

| 服务 | 部署位置 | 用途及主要配置 |
| --- | --- | --- |
| `candweb` | K3s | 考生端页面；配置考生端域名和服务端口 |
| `candbff` | K3s | 考生端 API；配置 `cfgserver`、Casdoor、Stripe 公钥、考试回调地址和服务间 TLS |
| `adminweb` | K3s | 管理端页面；配置管理端域名和服务端口 |
| `adminbff` | K3s | 管理端 API；配置 `cfgserver`、Casdoor 和服务间 TLS |

### 2.5 Go 业务微服务

以下服务全部部署在 K3s 集群：

| 服务 | 用途 | 主要配置 |
| --- | --- | --- |
| `gmid` | Casdoor 用户 ID 与业务 ID 映射 | PostgreSQL、Casdoor、NATS |
| `gcc` | 课程、认证、阶段、单元配置 | PostgreSQL、对象存储、NATS |
| `glms` | 课程资料、课件、试题、上传下载 | PostgreSQL、对象存储、Redis、NATS |
| `gprog` | 学习和认证进度流程 | PostgreSQL、Redis、NATS、相关服务地址 |
| `gmall` | 商品、订单和购买资格 | PostgreSQL、Redis、NATS、Stripe、会员/认证服务地址 |
| `gpay` | 支付请求和 Stripe Webhook | PostgreSQL、Stripe 密钥、Webhook Secret、回调地址 |
| `gmbr` | 会员方案和会员权益 | PostgreSQL、NATS、Casdoor 角色配置 |
| `gcreds` | 资格申请和证书 | PostgreSQL、对象存储、NATS |
| `gexam` | 考试预约和成绩回传 | PostgreSQL、Prometric/GEE、回调地址、NATS |
| `gmsg` | 站内消息 | PostgreSQL、NATS |
| `gmail` | 邮件发送 | PostgreSQL、NATS、SMTP |
| `gpdf` | 证书和凭证 PDF | PostgreSQL、对象存储、模板、NATS |
| `gaudit` | 审计记录 | PostgreSQL、NATS |

所有服务还需配置：镜像版本、副本数、CPU/内存 requests 和 limits、健康检查、日志级别、服务间地址及 TLS Secret。

### 2.6 配置工作

#### 2.6.1 网络和入口

1. 创建生产命名空间和镜像拉取 Secret；
2. 配置考生端、管理端和 Casdoor 的 Ingress；
3. 导入公网证书并启用 HTTPS；
4. 配置 DNS、负载均衡/WAF 回源和真实客户端 IP；
5. 配置 Stripe、Prometric/GEE 回调地址；
6. 验证集群到 PostgreSQL、Redis、对象存储、SMTP、Stripe 和考试系统的网络连通性。

#### 2.6.2 Secret 和运行参数

需要写入 Kubernetes Secret 或客户密钥系统的内容包括：

- PostgreSQL、Redis、NATS 和对象存储账号密码；
- TLS 证书、服务间 CA 和服务端证书；
- Casdoor Client ID、Client Secret；
- SMTP 账号和密码/令牌；
- Stripe Secret Key、Publishable Key、Webhook Secret；
- Prometric/GEE 账号和密钥；
- Grafana 管理员密码、企业微信 Webhook。

生产密码和密钥不得写入 Git 或镜像。

#### 2.6.3 外部系统

| 系统 | 我方需要完成 |
| --- | --- |
| 对象存储 | 创建 Bucket，配置权限、CORS、上传/下载地址和生命周期 |
| SMTP | 配置发件人，发送测试邮件，验证注册、订单、考试和证书邮件 |
| Stripe | 配置正式密钥、商品/价格引用、Webhook 地址，验证支付和退款/失败回调 |
| Prometric/GEE | 配置正式地址和凭据，完成预约、考试代码和成绩回传联调 |
| Grafana/企业微信 | 配置日志数据源、ERROR 告警、告警接收人并发送测试告警 |

### 2.7 数据初始化

#### 2.7.1 数据库结构

使用与正式发布版本完全一致的后台仓库 SQL/迁移脚本，为以下服务建立数据库表、索引和约束：

`cfgserver`、`gcc`、`glms`、`gprog`、`gmall`、`gpay`、`gmbr`、`gcreds`、`gexam`、`gmid`、`gmsg`、`gmail`、`gpdf`、`gaudit` 和 Casdoor。

执行要求：

1. 先创建 Database/Schema 和应用账号；
2. 执行表结构或迁移脚本；
3. 执行本版本要求的生产种子数据脚本；
4. 不导入测试账号、测试订单或演示数据；
5. 保存脚本版本和执行结果。

当前 Web 仓库不包含后台 SQL 脚本，具体文件名和执行顺序以正式后台发布包为准。

#### 2.7.2 Casdoor 数据

需要初始化：

- CFTP 组织；
- 管理端 Application；
- 考生端 Application；
- 两个应用的 Redirect URL；
- 初始超级管理员；
- 管理员、考生和会员相关角色及权限。

#### 2.7.3 业务基础数据

上线前需要在管理端录入或确认：

- 认证和课程 Pipeline、Stage、Unit；
- 课程资料、试题和考试配置；
- 资格定义和证书/PDF 模板；
- 会员方案；
- 商品 Bundle 及其认证/会员关联；
- Stripe Product ID、Price ID 和优惠码；
- 邮件模板和站内消息模板；
- Prometric/GEE 考试项目、表单代码和回调配置。

商品中的认证 ID、会员 ID 和价格配置必须引用本环境实际初始化的数据，不能继续使用旧环境 ID。

### 2.8 部署顺序

1. 验收客户提供的服务器、域名、证书、PostgreSQL、Redis、对象存储和外部账号；
2. 安装 K3s，配置命名空间、存储类和镜像仓库；
3. 初始化 PostgreSQL 数据库结构和生产种子数据；
4. 部署 NATS、Loki、Grafana、Vector；
5. 部署并初始化 Casdoor；
6. 部署 `cfgserver` 并录入正式运行参数；
7. 部署 `gmid`、`gcc` 和其他 Go 业务微服务；
8. 部署 `candbff`、`adminbff`、`candweb`、`adminweb`；
9. 配置 Ingress、3 个域名和 TLS 证书；
10. 初始化并核对业务基础数据；
11. 联调 SMTP、Stripe、Prometric/GEE 和对象存储；
12. 验证登录、课程、下单支付、会员、考试、证书、邮件、日志和告警。
