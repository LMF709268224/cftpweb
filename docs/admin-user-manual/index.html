课程配置使用手册

面向管理后台运营人员，说明课程的创建、内容维护、JSON 复用、版本管理和发布操作。

角色：课程运营难度：基础至进阶更新：2026-08-25

1. 功能概览

“课程配置”维护一门课程本身的学习内容。认证的阶段、价格、前置资格、免考和发证规则不在这里配置，它们分别属于“认证配置”和“商品配置”。

课程→章节→课时→正文 / 文件 / 视频
先课程，后认证，再商品课程发布后，才能在认证配置的“课程单元”中选择；认证发布后，再由商品绑定并配置价格。

2. 先理解这些概念

课程 GPath

课程业务系列的稳定标识，用来把同一门课程的不同版本关联起来。它不是课程标题，也不是文件地址。

课程 ID / ULID

某一个具体课程版本的唯一技术 ID，由系统生成。日常配置不需要手工填写。

版本

同一 GPath 下的版本号。克隆课程会创建同一门课程的新草稿版本。

状态

草稿可继续配置；已发布可供认证引用；已弃用是历史版本，不应继续用于新配置。

课程 GPath 应该怎么填

规则说明示例
必须以 / 开头使用分段路径表达业务归属。/courses/fcrc-foundation
只使用小写字符允许小写英文字母、数字、连字符 -、下划线 _ 和斜杠。/courses/cfta-level-1
新课程使用新 GPath不同课程不得共用 GPath，即使标题相似也要分开。A 与 B 使用不同路径
升级版本沿用 GPath通过“克隆”创建同一课程的新版本时，系统自动沿用原 GPath。v1、v2 共用一个 GPath
最长 255 个字符建议保持简短、稳定，不写版本号、日期或人员姓名。不要写 -v2 或 -2026
不要把 GPath 当成课程名称修改一门独立的新课程必须使用新的 GPath。复制其他课程的 JSON 后，也必须先修改 course_gpath，否则会与原课程系列发生冲突。

3. 新建课程

适用于从空白开始创建一门独立课程。点击页面右上角“新建课程”。

字段是否必填填写说明
课程标题必填考生端和管理后台显示的课程名称。建议使用正式、可识别的名称。
描述选填说明课程目标、适用对象和内容范围。不要在这里填写内部备注。
课程 GPath必填系统会随标题生成建议路径。新课程确认唯一即可，通常不要手动改成其他课程的路径。
时长分钟选填课程预计总学习时长，使用非负整数；未知时可以暂填 0，发布前补齐。
  1. 填写课程标题和描述标题应与对外课程名称一致。
  2. 展开“高级配置”检查 GPath确认是新路径，且不含大写字母、空格或中文。
  3. 填写课程时长按全部课时的预计学习时间汇总。
  4. 点击“保存课程”系统先创建草稿，随后进入课程详情继续配置内容。

4. 列表页按钮和操作

刷新

重新读取课程列表。其他管理员刚完成操作，或状态未及时更新时使用。

从 JSON 创建课程

把符合课程导入格式的 JSON 创建为新课程。适合复制既有课程结构后再调整。

新建课程

从空白草稿开始创建一门新课程。

查看详情

查看课程完整字段和可复制的课程 JSON，不直接修改数据。

编辑

进入课程详情，维护基础信息、章节、课时、资料和测验。

克隆

创建同一课程的新草稿版本，沿用原 GPath 和内容。不要用它创建另一门独立课程。

“克隆”和“从 JSON 创建课程”的区别克隆用于同一门课程升级版本；从 JSON 创建用于创建另一门课程，导入前必须改成新的 course_gpath。

5. 维护课程内容

课程草稿创建后，按章节、课时、资料和测验逐层维护。先建立章节，再把课时和章节测验挂到正确章节。

章节与课时

对象作用配置要点
章节组织课程内容的一级目录。填写标题和排序；建议先创建全部章节，再逐一添加课时。
课时考生实际学习的内容单元。选择所属章节、标题、排序和课时类型，再填写正文或上传对应资源。

两类课程资料

类型考生端用途何时使用
候选端辅助资料显示在考生端“课程资料 / Supplementary Materials”列表。按章节提供文章、视频、PDF 或外部链接时使用。优先通过单条表单维护。
普通文件资料课程级文件资源。提供下载文件或课程附件时使用，不等同于候选端辅助资料列表。
辅助资料看不到时检查什么确认已创建辅助资料配置，并且 supplementary_material.data_json 中存在有效记录；外部链接需要填写完整的 https:// 地址。

测验题库

  1. 点击“加载测验”刷新当前课程下所有课程级、章节级和课时级测验。
  2. 点击“新测验”选择挂载层级和所属对象，填写测验标题及规则。
  3. 添加题目和选项设置题型、分值、必答、正确选项和排序。
  4. 复核挂载位置挂错层级会导致考生在错误的学习节点看到测验。

6. 使用 JSON 创建课程

适合以现有课程为模板快速创建结构相似的新课程。JSON 不是备份恢复文件，导入前仍需人工检查业务字段。

  1. 在源课程点击“查看详情”切换到“可导入 JSON”并点击“复制 JSON”。
  2. 修改新课程字段至少修改标题和 course_gpath；按需要调整描述、时长、章节、课时和测验。
  3. 点击“从 JSON 创建课程”上传 JSON 文件或直接粘贴内容。
  4. 等待导入完成系统会依次创建课程草稿、章节、课时和章节测验，并在最后校验数量。
  5. 进入草稿补充未覆盖配置逐项检查资料、测验和文件资源后再发布。
当前 JSON 的覆盖范围支持课程基础信息、章节、课时和章节测验。普通资料、辅助资料、课程测验及课时测验需要在新课程中另行配置。
导入失败后不要连续点击重试失败时页面会保留已经创建的草稿 ID。先进入该草稿确认已导入到哪一步，避免重复创建章节或测验。

7. 推荐的配置与发布顺序

创建草稿→基础信息→章节→课时→资料→测验→复核→发布

发布会使课程成为可被认证配置引用的正式版本。同一 GPath 发布新版本时，旧的当前版本会进入历史状态，因此发布前应确认认证配置准备切换到哪个课程版本。

不要直接在生产内容上试配置先在草稿完成全部编辑和预览，再发布。已经发布的课程如果需要大幅调整，应使用“克隆”创建新草稿版本。

8. 常见问题

新课程和新版本有什么区别？

新课程是独立业务对象，必须使用新的 GPath；新版本是同一课程的升级，使用“克隆”创建并沿用原 GPath。

为什么 GPath 不能填中文或大写字母？

GPath 是跨服务使用的稳定技术标识。系统只接受以斜杠开头的小写字母、数字、连字符、下划线和分段斜杠。

改了课程标题，GPath 也要一起改吗？

通常不需要。标题是展示名称，GPath 是业务系列标识。课程已经创建后，不要因文案调整随意改变 GPath。

为什么认证配置里选不到刚创建的课程？

先确认课程是否已发布。认证配置只能绑定可用的已发布课程，草稿、已下架或不可用版本不会出现在选择列表中。

候选端为什么看不到课程资料？

先判断要展示的是“辅助资料”还是“普通文件资料”。候选端 Supplementary Materials 依赖辅助资料配置及其 data_json；普通文件不会自动出现在该列表。

JSON 导入后为什么有些资料或测验没有出现？

当前导入范围不包含普通资料、辅助资料、课程测验和课时测验。这些内容需要进入新草稿后另行配置。

9. 发布前检查清单

  • 课程标题和描述使用正式对外文案
  • GPath 与业务对象匹配且未误用其他课程路径
  • 课程时长已填写
  • 章节顺序正确且无空章节
  • 每个课时挂载到正确章节
  • 正文、文件或视频资源可正常打开
  • 辅助资料在候选端展示位置正确
  • 普通资料的文件名称和内容正确
  • 测验挂载层级正确
  • 题目分值、正确答案和排序已复核
  • JSON 创建的课程已补齐未导入内容
  • 确认发布的是目标课程版本

认证配置使用手册

面向认证运营人员，说明认证管线的阶段、课程单元、免考、资格条件、证书、报读限制和版本发布。

角色：认证运营难度：进阶更新：2026-08-25

1. 功能概览

“认证配置”把已发布课程组织成一条可报读的认证管线，并规定购买门槛、课程免考、结业审核、最终发证和跨管线互斥规则。课程内容和商品价格不在这里维护。

认证管线→阶段→课程单元→终审→最终证书
依赖关系先在“课程配置”发布课程，在“资格定义”和“证书模板配置”准备资格与 PDF 模板，再完成认证配置；认证发布后，商品才能引用并配置价格。

2. 先理解这些概念

认证 GPath / 资源路径

认证业务系列的稳定路径，也是跨服务识别管线的关键字段。同一认证的不同版本沿用它，不同认证必须使用不同路径。

认证 ID / ULID

某个具体认证版本的唯一 ID，由系统生成。商品和流水最终会关联到具体版本。

阶段

认证学习流程的分组，例如 L1、L2。阶段按排序依次展示，每个阶段至少包含一个课程单元。

课程单元

阶段中的学习和计费单位，绑定一门已发布课程，可附带考试、免考及单元证书规则。

对象新业务对象同一对象升级版本
GPath使用新的唯一 GPath沿用原 GPath
创建方式点击“新建认证”在原版本上点击“克隆版本”
结果形成独立认证系列形成同一认证的下一草稿版本
不要通过修改名称来区分不同认证名称只是展示文案。把另一条认证误用为相同 GPath，会被识别成同一认证的版本，影响发布切换、商品引用和互斥判断。

4. 配置阶段

阶段用来表达认证的学习顺序和业务层级。先建立阶段，再进入“课程单元”页签绑定课程。

  1. 点击“新阶段”按业务顺序创建 L1、L2 等阶段。
  2. 填写名称和排序排序建议使用 1、2、3 等清晰序号，避免重复。
  3. 为阶段添加课程单元每个阶段至少需要一个已绑定课程的单元，结构才能保存。
  4. 检查阶段汇总确认单元名称、课程、考试代码和免考状态与预期一致。

5. 配置课程单元、考试与免考

字段作用配置要点

名称单元对外显示名称可与课程名一致，也可使用认证体系内的正式单元名。
排序决定同一阶段内的顺序同阶段保持唯一且连续。
关联课程指定实际学习内容只能选择已发布且可绑定的课程；绑定的是具体课程版本。
Program / Exam Code / Form Code对接考试项目、考试和试卷仅在该单元涉及考试时按考试系统约定填写。

免考规则怎么配

  1. 勾选“允许免考”未勾选时，即使考生持有相关资格，后台也不会自动免除该单元。
  2. 勾选一项或多项豁免资格考生持有其中任一有效资格即可满足该单元免考条件。
  3. 保存认证结构商品下单时，GMALL 会自动识别考生已持资格，应用免考并计算减免后的金额。
考生端不需要重复勾选自动免考项系统会把自动识别的免考与考生手工补充的其他免考去重合并；如果某阶段全部单元都被免考，该阶段实例化后会自动完成。
单元证书不是最终认证证书“单元完成后签发的资格 / 单元证书 PDF 模板”只在完成该单元就要单独发证时填写。认证全部完成后的主证书，应配置在“最终颁发证书”。

9. 保存、复核与发布

创建草稿→阶段→课程单元→资格与证书→报读限制→保存结构→发布
  1. 先保存基础信息确认名称、分类、描述和 GPath。
  2. 完成全部结构层级每次调整后点击“保存结构”，页面中的临时修改才会写入后台。
  3. 使用“完整结构 JSON”复核高级编辑区适合检查底层结构；“应用到分层视图”只更新页面状态，仍需再次保存结构。
  4. 发布前做跨模块检查确认课程已发布、资格定义可用、PDF 模板正确、商品准备绑定新版本。
  5. 点击发布并回归购买流程用无资格、持初阶资格、持高阶资格和存在进行中订单的测试账号分别预检。
已发布或已下架结构不可直接编辑需要调整时使用“克隆版本”，在新草稿完成修改和验证后再发布。不要通过下架当前版本来代替版本升级。

10. 常见问题

为什么课程单元里选不到刚创建的课程？

课程单元只显示可绑定的已发布课程。先到课程配置确认目标版本已发布，草稿、已下架或未启用课程不能绑定。

没有 CFTA 的考生也要能购买 CFTP，是否应该删除 CFTA 前置资格？

是。前置准入资格表示购买前必须持有。允许直接购买时应留空，并把 CFTA 课程加入 CFTP；已有 CFTA 的考生通过该单元的免考规则自动减免。

配置了豁免资格，为什么没有自动免考？

同时检查该课程单元是否勾选“允许免考”、豁免资格是否选择正确、考生持有的资格是否有效，以及认证结构是否已保存并随当前版本发布。

为什么 CFTA 和 CFTP 互斥只在一个方向生效？

互斥关系不是自动双向的。需要在 CFTA 中配置 CFTP GPath，同时在 CFTP 中配置 CFTA GPath。

禁止报读资格与前置准入资格有什么区别？

前置准入是“必须持有才可以买”；禁止报读是“持有任一项就不能买”。两者方向相反，不能配置成同一个业务含义。

最终颁发证书只选资格定义可以吗？

不可以。最终证书必须同时选择资格定义和证书 PDF 模板，否则发布前结构校验会失败，或后续无法正确生成证书。

角色：商品运营难度：进阶更新：2026-08-25

1. 功能概览

“商品配置”决定商城实际卖什么、每个收费节点使用哪个 Stripe 价格，以及考生购买后获得哪条认证或会员权益。它不维护课程内容，也不定义认证的阶段和资格规则。

已发布认证 / 会员→商品草稿→Stripe 定价→价格复核→发布
先准备交付内容和 Stripe 价格认证或会员方案需要先达到可用状态；收费项使用的 Stripe Product 和 Price 也应提前创建并核对环境、币种和金额。

2. 先理解这些概念

商品 GPath / 商品路径

商城购买入口使用的稳定业务路径。同一商品的不同版本沿用它，独立商品必须使用新的唯一路径。

Bundle ULID

某个具体商品版本的唯一 ID，由系统生成。商品绑定和订单快照最终使用具体版本。

关联内容

购买后实际交付的认证或会员权益。当前管理页面支持最多一条认证和一个会员权益，也支持两者组合销售。

价格配置

商品各收费节点对应的 Stripe Product ID 和 Price ID，包括课程准入、重考、免考、会员和审核等。

展示价格

从 Stripe 价格计算出的列表区间，不是手工输入字段。最低价按首阶段课程准入价计算，最高价按全部阶段课程准入价计算，并叠加会员价格。

版本

同一商品 GPath 下的配置版本。克隆会复制关联内容、价格、封面和文案，形成新草稿版本。

场景操作商品 GPath
创建另一种独立商品新建商品使用新的唯一路径
同一商品升级认证版本或价格克隆为草稿沿用原路径
认证与会员组合销售新建或克隆后添加两类关联内容使用能稳定代表该组合的路径
不要把商品路径当成标题修改名称和描述可以调整，GPath 表示商品系列。误用其他商品的 GPath 会被识别为同一商品的新版本，发布时可能替换错误的商城入口。

3. 新建商品

新建时先选择购买后交付的内容，再填写展示信息。系统会根据选择生成关联内容 JSON，通常不需要手工编辑。

组合商品一条认证 + 一个会员权益两项不能重复，发布时两者都必须可用
字段是否必填填写说明

商品路径必填稳定购买入口，例如 /gcc/pipeline/core/cftp；新商品确认唯一。
封面选填优先使用“上传封面图”，系统会填写 Object Key 和文件校验值。没有素材时两项都留空。

高级 JSON通常不修改items_json 由关联内容自动生成；创建时 pricing_json 可保持 {}，之后在结构与价格页维护。
  1. 选择关联内容确认具体认证或会员版本，不要只看名称。
  2. 填写名称、描述和封面封面上传后不要手工拆改 Object Key 与校验值。
  3. 展开高级配置检查商品路径独立商品使用新路径，同一商品版本升级使用克隆。
  4. 点击“创建草稿”进入商品详情继续维护结构和价格。

商品路径不会在基础信息中随名称更新它是版本系列标识。需要创建另一个独立商品时回到列表使用“新建商品”，不要克隆后只改名称。

5. 配置课程单元价格

进入“结构与价格”后，页面会读取当前关联认证的阶段和课程单元。每个收费项都必须填写 Stripe Product ID 与 Price ID，不能只填其中一个。

7. 复核价格预览和展示价格

价格预览把关联内容和 Stripe ID 按业务含义展开，比直接阅读 JSON 更适合发布前复核。

“同步展示价格”做什么

它会重新向支付服务验证 Stripe Price，计算并更新商品列表中的最低价、最高价和币种。保存结构与价格时会同步当前商品；列表顶部按钮可重新同步未弃用商品，适合 Stripe 金额调整后刷新展示。

展示区间的计算范围最低价为会员价格加首阶段课程准入价，最高价为会员价格加全部阶段课程准入价。重考、免考申请、资格审核和解锁价格不计入这个展示区间。
币种必须一致商品中配置的全部 Stripe Price 必须使用同一币种，否则发布会失败。展示金额不在后台手填，以 Stripe Price 的实际值为准。

8. 商品版本升级与替换认证

认证发布新版本后，旧商品不会自动改绑。推荐先克隆商品为新草稿，再在“结构与价格”中替换绑定认证。

  1. 在当前商品点击“克隆为草稿”系统沿用商品 GPath，并复制文案、封面、关联内容和价格。
  2. 选择新绑定认证确认新认证已经发布，名称相同也要核对认证 ULID。
  3. 点击“替换认证并保存”系统更新关联认证，并按旧、新认证的课程单元顺序迁移单元价格 ID。
  4. 逐项复核课程单元价格检查每个新单元对应的 Product / Price，补齐新增单元，删除不再存在的收费项。
  5. 检查认证解锁价格旧认证 ID 会替换成新认证 ID；普通认证不需要解锁费时，应明确移除该项。
单元价格迁移依赖顺序，不理解业务差异如果新认证调整了阶段、单元数量或排序，自动映射可能对应错误。替换完成只代表结构已迁移，不代表价格已经业务确认。

10. 常见问题

新建商品时为什么选不到认证？

先确认认证已经发布且处于可用状态，再刷新关联内容选项。商品最终发布时，后台也会重新校验关联认证或会员是否为 Active。

为什么只填 Price ID 不能保存？

每个收费项必须同时填写对应的 Stripe Product ID 和 Price ID；两者缺一都会被前端和微服务拒绝。

已有 CFTA 资格自动免考，还要配置“免考申请价格”吗？

不需要。自动免考由认证配置决定。只有业务对人工免考申请单独收费时，才配置该单元的免考申请 Product 和 Price。

为什么普通认证商品不需要认证解锁价格？

认证解锁价只用于先付解锁费再购买的特殊流程。普通认证套餐直接按课程单元收费，留空即可，不应为了发布而虚构一组 Stripe 价格。

替换认证版本后，旧价格能直接发布吗？

不能直接认定正确。系统按课程单元顺序迁移 ID，不会判断新旧单元的业务含义；必须逐项核对并处理新增、删除或重排的单元。

为什么列表展示价格没有更新？

先保存结构与价格，再点击“同步展示价格”。如果仍失败，检查 Stripe Price 是否有效、参与计算的价格是否同币种，以及支付服务是否可用。

商品路径可以直接使用认证 GPath 吗？

可以在不同服务中采用相同业务路径，当前页面也以此作为常见示例；但商品路径本身仍必须在商品系列内唯一。认证加会员的组合商品建议使用能明确代表组合的独立路径。

资格定义使用手册

1. 功能概览

“资格定义”维护资格的基础字典，包括名称、分类、资源路径、获取说明和申请时所需材料。创建完成后，再到“认证配置”把它放到具体业务位置。

资格定义→认证配置引用→申请 / 校验 / 发证 / 免考
分类不等于业务规则选择“认证资格”或“免考资格”只是在资格列表中标记用途。系统是否准入、禁购、终审、发证或免考，取决于该资格 ID 在认证配置中被引用的位置。

2. 资格分类怎么选

分类推荐用途示例
认证资格由认证管线或课程单元正式颁发的证书资格CFtA Certification、CFtP Certification
免考资格通过人工申请取得、用于豁免某个课程单元的资格CFtP L1A Finance Exemption
通用资格工作经验、执业条件等非学位类材料资格CFtP Work Experience Proof

3. 新建资格

点击页面右上角“新建资格”，完成基础信息和文件约束后创建。资格 ID 由系统生成，不需要手工填写。

字段是否必填填写说明
名称必填使用正式、可区分的资格名称；后续认证配置会按该名称供运营人员选择。
分类必填按资格本身选择认证、免考、通用或学业类，不要按当前页面的临时使用位置分类。
资源路径必填资格的唯一资源标识和材料上传权限对象，例如 /gcc/credential/cftp-certification。

描述必填说明资格代表什么、适用范围和审核口径。
文件约束按场景只有考生需要上传材料申请该资格时才添加；系统自动颁发的证书通常不需要。
  1. 先确认资格是否已经存在按名称和业务含义检查列表，避免为同一资格重复创建多个 ID。
  2. 选择分类并填写说明名称和描述应能让后续配置人员准确识别。
  3. 确认唯一资源路径新资格使用新路径，不复制已有资格路径。
  4. 按申请流程添加文件约束逐项确定文件名称、类型以及是否必填。
  5. 创建后核对详情记录资格 ID，再到认证配置引用。

资源路径（Resource Path）是资格在系统底层的稳定唯一标识之一，同时用于控制考生上传该资格材料的权限。它不是网页地址，也不是认证 GPath。

8. 常见问题

“认证资格”和“免考资格”会自动触发不同流程吗？

不会。分类用于表达资格性质和帮助运营识别；具体流程取决于资格 ID 被配置到前置、终审、最终证书、禁止报读或课程单元豁免中的哪一处。

系统自动颁发的证书需要添加文件约束吗？

通常不需要。文件约束用于考生手工申请资格时上传证明。系统颁发的证书应在认证配置中绑定资格定义和证书 PDF 模板。

同名资格为什么不能互相替代？

系统按资格定义 ID 判断，不按显示名称判断。重复创建同名资格会产生两个独立的业务对象。

已有高阶资格禁止购买初阶认证，要配置在哪里？

在初阶认证的“禁止报读资格”中选择高阶认证资格。互斥认证管线则在双方“互斥认证管线”中分别配置，两者作用不同。

资源路径写错了，可以在页面修改吗？

当前页面详情只读，没有编辑入口。不要继续引用错误定义，也不要擅自创建同名替代项；应提供资格 ID、错误路径和引用情况给技术团队处理。

1. 功能概览

“证书模板配置”维护生成 PDF 时使用的完整 HTML 和 CSS。模板本身不会发证；创建后必须在认证配置的最终证书或课程单元证书中绑定，系统发证时才会使用。

资格定义+证书模板→认证配置绑定→完成条件→生成 PDF

2. 先理解这些概念

模板 ID / ULID

模板的稳定唯一标识，由系统创建。认证结构引用的是这个 ID，不按模板名称查找。

模板版本

每次编辑并保存同一个模板，版本号增加，但模板 ID 不变。

HTML 模板

完整 HTML 文档，包含页面内容、CSS、图片和 Go 模板变量。

模板参数

发证服务传入的动态数据，例如姓名、证书编号、课程名和签发日期。

配置对象负责内容在哪里关联

证书模板PDF 版式、文字、图片和变量位置与资格定义一起绑定
模板变量姓名、编号、课程、日期等运行时数据由微服务按发证场景传入，不在本页面手工填写

3. 新建和编辑模板

新用途或需要保留旧版外观时使用“新建模板”；仅修正文案或样式且允许后续证书统一采用新外观时，可直接编辑现有模板。

字段是否必填填写说明
模板 ID系统生成创建后只读，是认证配置实际保存的引用值。
模板名称必填建议包含证书用途或认证名称，便于配置人员区分。
描述选填写明适用认证、版式或语言，避免使用“test”“新版”等模糊名称。

4. 模板变量怎么使用

PDF 模板使用 Go html/template 语法，变量必须写成 {{ .Name }} 这种形式。变量名区分大小写，点号和大括号都不能省略。

发证场景可用变量值的含义
认证最终证书{{ .Name }}考生姓名
认证最终证书{{ .CandidateNo }}当前由发证流程传入的证书编号（degree number），不是考生 ULID，也不是登录账号
课程单元证书{{ .Name }}考生姓名
课程单元证书{{ .Course }}认证配置中该课程单元的名称提示
课程单元证书{{ .IssueDate }}签发日期，格式为 YYYY-MM-DD，例如 2026-08-21
不要跨场景使用变量当前认证最终证书只传入 Name 和 CandidateNo；课程单元证书传入 Name、Course 和 IssueDate。最终证书模板写 {{ .IssueDate }} 或 {{ .Course }} 不会自动从 PDF 请求的其他字段合并进来。

最小示例

<h1>Certificate of Completion</h1>
<p class="name">{{ .Name }}</p>
<p class="course">{{ .Course }}</p>
<p class="date">{{ .IssueDate }}</p>
编号字段的显示文案由模板决定如需展示证书编号，可将 {{ .CandidateNo }} 放在 “Certificate No.” 或中英文都适用的标签旁；不要把它标成考生 ID，除非业务已确认其语义。

5. HTML、CSS、图片和字体

项目配置建议常见问题
页面尺寸在 CSS 中明确 @page { size: A4 landscape; } 或业务要求的尺寸，并把页面边距设为确定值。未设打印尺寸会导致缩放、分页或边框被裁切。
固定布局证书画布使用稳定宽高、定位和间距，不依赖浏览器窗口大小。响应式网页布局在 PDF 中可能错位。
背景与颜色使用 print-color-adjust: exact，同时保持文字与背景有足够对比。打印渲染可能淡化背景色。
图片使用 PDF 生成服务能够访问的稳定地址，保存前确认 Logo、边框和签名均能在预览中加载。本机路径、登录后才能访问的地址或短期签名 URL 会失效。
字体使用生成服务中可用的字体并提供通用回退字体；中文证书必须实际生成一张 PDF 验证汉字。管理员电脑能显示不代表 GPDF 容器也安装了同一字体，缺字时可能显示方框。
动态文本为姓名、课程名和编号预留足够宽度，允许合理换行或限制字号。长姓名和长课程名容易覆盖固定文案或签名。
预览通过不等于 PDF 一定相同右侧预览运行在管理后台浏览器，最终 PDF 由 GPDF 服务中的浏览器环境生成。字体、远程图片、打印分页和网络访问仍需用真实发证流程验证。

6. 预览和多语言

HTML 预览

用于快速检查页面布局和静态资源。它不会模拟真实考生数据，也不会替换模板变量。

设置多语言

当前可维护模板名称和描述的翻译，便于后台识别；HTML 模板正文不会自动生成另一种语言版本。

需要不同语言证书时如果中英文证书正文、固定文案或布局不同，应分别建立明确命名的模板，并在对应认证版本中绑定；不要期待“设置多语言”自动翻译 HTML。

7. 模板版本和认证引用

编辑现有模板会保留模板 ID，并将版本号加一。所有仍引用该模板 ID 的认证，在之后新生成 PDF 时会使用最新模板内容。

操作模板 ID影响范围
编辑并保存现有模板不变后续新生成或重试生成的 PDF 使用更新后的内容
新建模板生成新 ID不会自动替换任何认证，需要在认证配置中重新选择
查看已生成证书无变化已经生成并保存的旧 PDF 不会因模板编辑自动更新
正式模板的大改动不要直接覆盖如果需要保留某批证书的旧版式，或新认证版本要使用不同法律文案，应新建模板，再创建或克隆认证草稿绑定新模板。直接编辑会影响所有继续引用旧模板 ID 的后续发证。
  1. 在模板列表核对模板 ID 和当前版本名称相似时以 ID 为准。
  2. 在认证配置绑定正确组合同时核对资格定义 ID 和 PDF 模板 ID。
  3. 使用测试考生完成一次真实发证验证姓名、编号、课程、日期、字体、图片和下载链接。
  4. 再发布认证或投入正式使用已发布认证不能直接修改结构时，先克隆新草稿版本。

8. 常见问题

为什么预览里仍然显示 {{ .Name }}？

右侧预览只渲染当前 HTML，不注入测试考生参数，因此模板占位符会原样显示。真实发证时才由微服务传入对应值。

为什么证书没有课程名或日期？

先确认模板用于课程单元证书，并使用了正确大小写的 {{ .Course }} 与 {{ .IssueDate }}。认证最终证书当前不提供这两个模板变量。

为什么 CandidateNo 不是考生 ID？

这是现有接口字段名，当前发证流程传入的是证书编号（degree number）。模板上的固定标签应按证书编号表达，不要据字段名推断为考生 ULID 或登录账号。

日期应该怎样显示才适合中英文？

课程单元证书的 IssueDate 已格式化为 YYYY-MM-DD，例如 2026-08-21，无需在 HTML 中再次处理 RFC3339 时间。

中文姓名显示方框，改 HTML 字体名就够了吗？

不一定。最终 PDF 在 GPDF 容器中生成，所选中文字体必须在该环境中真实可用。保留回退字体后仍应生成 PDF 验证；缺字体需要由部署侧安装或提供可加载的字体资源。

保存模板后，已有证书会自动更新吗？

不会。已生成 PDF 是历史产物；模板更新只影响之后新生成或重新生成的证书。

4. 资源路径、封面和访问权限

资源路径的作用类似业务主键候选端会用它进行权限判断，同一路径还用于识别资源包的现行发布版本。随意修改可能导致原有授权失效，或把本应独立的资源误认为同一系列。
场景资源路径怎么处理结果

从旧包复制内容制作另一个业务资源保存前改成新的路径避免覆盖旧系列，也避免沿用旧权限
public 不等于自动公开分类只描述内容类型。候选人是否可见仍由资源路径对应的权限决定；新路径发布前必须同步确认授权配置。

9. 常见问题

为什么新建资源包时不能上传封面？

上传接口需要资源包 ID。先保存草稿，从列表进入编辑页，再上传封面并保存。

为什么新建资源文件时上传按钮不可用？

同样需要先生成资源文件 ID。先保存所属资源包、标题和类型，再编辑上传文件或视频。

分类选 public 后，所有考生都会看到吗？

不会。分类用于归类，候选端还会检查资源路径权限。新资源路径必须同步完成授权配置。

为什么资源包上架失败？

先检查封面 Object Key 和 SHA256；再逐个检查文件。Video 必须有视频 UID，PDF/ZIP 必须有真实存在的 Object Key、文件信息和 64 位 SHA256。

为什么不能删除已上架资源包或其中的文件？

后端只允许删除草稿数据。需要停止展示时先下架；正式版本调整优先克隆新草稿，避免破坏历史。

为什么上架新版本后旧版本显示“已废弃”？

同一资源路径只保留一个现行 Active 版本。新版本上架后旧 Active 自动转为 Deprecated，这是正常的版本替换行为。

版本字段可以改成 2.0 吗？

不可以。它是后端乐观锁版本，保存和状态操作会自动递增，不是展示给用户的语义版本。

10. 上架前检查清单

  • 标题和描述能清楚说明资源用途
  • 新资源使用新路径，同系列版本保留原路径
  • 资源路径对应的候选人权限已配置
  • 分类没有被误当成访问权限
  • 资源包封面已上传且可以访问
  • 封面 SHA256 为正确的 64 位值
  • 所有文件挂在目标资源包版本下
  • 文件标题、描述和排序已复核
  • Video 均有有效视频流 UID
  • PDF/ZIP 的文件名、大小、Object Key 和 SHA256 完整
  • 没有重复文件名、哈希或视频 UID
  • 克隆版本复用的存储对象仍真实存在
  • 多语言标题和描述已按需补充
  • 已用有权限和无权限账号验证候选端结果
  • 确认上架的是目标资源路径的正确草稿

认证实例 ID这位考生本次认证流程的唯一标识日志排查和技术支持时优先提供
当前阶段 ID当前正在处理的阶段实例与阶段页中的阶段实例 ID 对照
阶段数 / 课程单元数本实例快照中的结构数量与认证配置数量不一致时，先确认实例创建时间和配置版本
配置 ID 与实例 ID 不同带有“配置”的 ID 指向定义；不带“配置”的实例 ID 指向本次运行记录。提交问题时不要只提供课程或认证名称。

4. 阶段与课程单元

  1. 先看阶段顺序和当前阶段确认考生是否停留在预期阶段，避免检查错误阶段。
  2. 再看该阶段的课程单元逐项确认学习进度、考试 ID 和单元状态。
  3. 结合考试管理核对考试存在考试 ID 时，到考试管理确认预约、成绩和状态流转。
  4. 最后查看状态日志确认系统是否已经接收并处理完成事件。

5. 状态日志

状态日志记录认证、阶段和课程单元的状态变化。点击“加载状态日志”后，可按发生时间查看变更前后状态、对象类型和触发来源，并打开详情查看原因。

日志字段排查意义
对象类型与对象 ID区分变化发生在认证、阶段还是课程单元
原状态 / 新状态确认实际发生的状态迁移
触发来源区分系统、认证驱动、管理员或考生触发
原因代码与原因说明判断正常自动推进、人工干预或异常原因
发生时间与考试回调、审核记录和服务日志对齐

6. 人工操作与限制

人工操作用于处理经过确认的异常状态，不是日常推进认证的标准流程。操作前必须核对考生、认证实例和当前状态，并在原因中记录审批或工单依据。

操作允许条件结果与风险
推进下一阶段认证为“运行中”，且当前阶段已经“完成”触发认证驱动继续推进；按钮禁用时应先查未完成单元和日志
终止认证认证尚未“已完成”或“已取消”认证变为“已取消”，当前未完成阶段和单元会被收尾；此页不提供恢复操作
强制完成课程单元课程单元必须为 `EXAM_FAILED`直接改为完成，并可能触发阶段继续推进；只能在业务审批后使用
重置为待预约考试课程单元必须为 `EXAM_FAILED`允许重新进入考试预约流程，不会改写原考试结果
终止认证不会同步终止考试如果课程单元已经关联考试 ID，认证服务只记录告警，考试实例需要在考试侧另行核对和处理。终止前务必检查课程单元和考试管理。
不要连续点击人工操作系统会对状态和并发更新再次校验。失败时先刷新详情和日志；记录认证实例 ID、课程单元实例 ID、错误提示和操作原因后再处理。

7. 最终审核与证书任务

课程阶段完成后，如果认证配置了发证前终审材料，认证会进入“等待最终资格”；材料应在审核中心处理。审核通过后进入发证流程，“证书任务”页签会在发证中或已完成时显示。

现象处理方式
等待最终资格到审核中心核对该考生的终审材料，不要手工推进阶段
发证中查看证书任务状态、模板参数和错误信息，等待任务完成
证书任务失败先修复模板、参数、存储或服务异常，再执行一次重试
认证已完成可查看已生成证书；下载链接过期时重新打开详情获取新链接
重试不能修复配置错误模板缺失、模板参数不匹配或下游服务异常未解决时，重复重试只会再次失败。应先查看任务错误信息并处理根因。

8. 查询与排查检查清单

  • 考生 ULID 和认证实例 ID 已确认无误
  • 已区分认证、阶段和课程单元三层状态
  • 当前阶段与阶段顺序符合预期
  • 每个未完成课程单元的学习进度和考试 ID 已核对
  • 有关联考试时已在考试管理检查预约和成绩
  • 状态日志中的对象、触发来源和发生时间已核对
  • 等待最终资格时已到审核中心检查材料
  • 发证失败时已先处理任务错误根因
  • 人工操作前已取得审批并填写可追溯原因
  • 终止认证时已另行确认关联考试是否需要处理

站内信使用手册

面向运营和客服人员，说明如何选择收件人、使用模板和 Payload 发送站内通知，以及维护模板、查看发送记录和处理失败。

角色：运营 / 客服难度：基础至进阶更新：2026-08-25

1. 功能概览

站内信用于向考生端消息中心发送通知。消息正文不能在发送页面直接输入，而是由“模板 + Payload JSON”渲染生成；同一模板可以向一个或多个考生发送不同业务场景的通知。

准备模板→选择收件人→选择消息类型→填写 Payload→发送并复核
页签用途是否会产生外部影响
发送站内信选择收件人、模板、消息类型和参数并立即发送是，点击发送成功后考生端会出现消息
发送记录查看系统自动消息和管理员手工消息的发送记录否，只读查询
模板管理创建自定义模板，查看或编辑已有模板是，修改模板会影响后续使用该路径的消息

2. 发送一封站内信

  1. 刷新用户和模板进入页面后先点击右上角“刷新用户”和“刷新模板”，避免使用过期列表。
  2. 选择收件用户按姓名与 26 位用户 ULID 双重核对。可以多选；“全选”只选择当前页面已经加载的用户列表。
  3. 选择模板下拉框同时显示模板标题和唯一模板路径，优先按路径确认业务场景。
  4. 选择消息类型根据实际内容选择系统通知、考试提醒、成绩报告、支付通知或其他。
  5. 填写 Payload JSON将模板变量对应的空值替换为真实数据，确认字段名、类型和 JSON 格式。
  6. 小范围验证后发送重要或批量通知先发送给测试账号，确认标题和正文渲染正确，再选择正式收件人。
  7. 检查发送记录成功提示中的数量应与实际收件人数一致，并在发送记录中核对模板、收件人和参数。
发送成功后不能在当前页面修改或撤回页面没有撤回操作。使用“全选”或批量发送前必须再次核对收件人、模板和 Payload，不要把测试消息发送给正式考生。

3. 消息类型与 Payload JSON

消息类型适用内容示例
系统通知一般系统状态或服务通知资料更新、功能状态变化
考试提醒考试预约、开考前提醒等考试时间和确认号提醒
成绩报告考试结果或成绩处理通知成绩已发布、结果可查看
支付通知付款、退款或支付异常支付成功、支付失败
其他无法归入以上类别的通知经审批的临时运营通知

选择模板后，页面会从标题和正文中的 {{Variable}} 自动提取变量，并生成带空值的 Payload。管理员必须填写真实值；Payload 必须是 JSON 对象，不能是数组、字符串或 null。

{
  "CandidateName": "Li Ming",
  "PipelineName": "CFtP Accreditation Track"
}
字段名必须完全一致CandidateName、candidateName 和 Candidate Name 是三个不同字段。字段是否必填、值是字符串还是数字，以所选模板的“参数规则 JSON Schema”为准。
空字符串不等于已填写页面自动生成的变量值默认是空字符串。发送前应逐项替换；如果 Schema 没有限制空值，系统可能允许发送，但考生看到的标题或正文会缺少内容。

4. 创建自定义模板

字段含义配置规则
路径模板的唯一业务标识建议使用 /msg/业务/场景/admin；保存后不可在编辑页修改
标题模板考生消息列表显示的标题必填，最多 255 个字符；变量使用 {{Variable}}
内容模板考生打开消息后看到的正文必填；正文中的每个变量都要在 Schema 中定义
描述给管理员看的用途说明建议写明触发场景、维护团队和收件人范围
参数规则 JSON Schema定义 Payload 可用字段、类型和必填项必须是合法 JSON Schema；自定义模板建议显式限制必填字段

5. 模板变量与参数规则

{
  "type": "object",
  "properties": {
    "CandidateName": { "type": "string", "minLength": 1 },
    "PipelineName": { "type": "string", "minLength": 1 }
  },
  "required": ["CandidateName", "PipelineName"],
  "additionalProperties": false
}
模板与 Schema 必须同步标题或正文新增 {{PipelineName}} 时，Schema 的 properties 也必须增加同名字段，否则模板保存会失败；发送时缺少 required 字段也会失败。
内置模板属于服务协议以 /msg/... 表示业务事件的现有模板可能被认证、商城、审核等服务自动调用。不要随意修改路径、变量名或参数结构；内置模板的参数 Schema 由微服务维护，运营仅在确认上下游兼容后修改文案。

7. 常见问题

选择模板后为什么 Payload 自动出现字段？

页面会读取模板详情，并扫描标题和正文中的 Mustache 变量生成 JSON。它只是填写助手，最终仍以模板的 JSON Schema 校验结果为准。

为什么提示 Payload JSON 格式错误？

检查双引号、逗号和大括号，并确认最外层是对象。JSON 不支持单引号、注释或末尾多余逗号。

JSON 格式正确，为什么仍然发送失败？

通常是字段缺失、字段类型不符或存在 Schema 不允许的字段。打开模板详情核对参数规则，再检查每个变量名和取值。

为什么找不到刚创建或修改的模板？

点击右上角“刷新模板”；如果仍未出现，检查保存是否成功以及当前模板分页。

发送成功但考生说没有看到怎么办？

在发送记录中按时间定位消息，核对接收用户编号、模板和参数；确认考生登录的是同一账号，再由技术人员根据站内信编号排查。

可以删除模板或撤回消息吗？

当前管理页面没有提供模板删除和消息撤回操作。已发送消息应视为不可编辑；确需处理时记录消息编号并走技术与业务审批流程。

8. 发送前后检查清单

  • 用户和模板列表已经刷新
  • 收件人姓名与 26 位用户 ULID 已双重核对
  • 没有误用“全选”发送给无关考生
  • 模板路径与本次业务场景一致
  • 消息类型与实际内容一致
  • Payload 是合法 JSON 对象
  • 所有模板变量均已填写且字段名完全一致
  • 字段类型和必填项符合模板 JSON Schema
  • 批量发送前已经用测试账号验证标题和正文
  • 发送成功数量与收件人数一致
  • 发送记录中的用户、模板和参数已经复核
