课程配置使用手册

面向管理后台运营人员，说明课程的创建、内容维护、JSON 复用、版本管理和发布操作。

角色：课程运营难度：基础至进阶更新：2026-08-25

1. 功能概览

“课程配置”维护一门课程本身的学习内容。认证的阶段、价格、前置资格、免考和发证规则不在这里配置，它们分别属于“认证配置”和“商品配置”。

课程→章节→课时→正文 / 文件 / 视频
先课程，后认证，再商品课程发布后，才能在认证配置的“课程单元”中选择；认证发布后，再由商品绑定并配置价格。

2. 先理解这些概念

课程 GPath

课程业务系列的稳定标识，用来把同一门课程的不同版本关联起来。它不是课程标题，也不是文件地址。

课程 ID / ULID

某一个具体课程版本的唯一技术 ID，由系统生成。日常配置不需要手工填写。

版本

同一 GPath 下的版本号。克隆课程会创建同一门课程的新草稿版本。

状态

草稿可继续配置；已发布可供认证引用；已弃用是历史版本，不应继续用于新配置。

课程 GPath 应该怎么填

规则说明示例
必须以 / 开头使用分段路径表达业务归属。/courses/fcrc-foundation
只使用小写字符允许小写英文字母、数字、连字符 -、下划线 _ 和斜杠。/courses/cfta-level-1
新课程使用新 GPath不同课程不得共用 GPath，即使标题相似也要分开。A 与 B 使用不同路径
升级版本沿用 GPath通过“克隆”创建同一课程的新版本时，系统自动沿用原 GPath。v1、v2 共用一个 GPath
最长 255 个字符建议保持简短、稳定，不写版本号、日期或人员姓名。不要写 -v2 或 -2026
不要把 GPath 当成课程名称修改一门独立的新课程必须使用新的 GPath。复制其他课程的 JSON 后，也必须先修改 course_gpath，否则会与原课程系列发生冲突。

3. 新建课程

适用于从空白开始创建一门独立课程。点击页面右上角“新建课程”。

字段是否必填填写说明
课程标题必填考生端和管理后台显示的课程名称。建议使用正式、可识别的名称。
描述选填说明课程目标、适用对象和内容范围。不要在这里填写内部备注。
课程 GPath必填系统会随标题生成建议路径。新课程确认唯一即可，通常不要手动改成其他课程的路径。
时长分钟选填课程预计总学习时长，使用非负整数；未知时可以暂填 0，发布前补齐。
  1. 填写课程标题和描述标题应与对外课程名称一致。
  2. 展开“高级配置”检查 GPath确认是新路径，且不含大写字母、空格或中文。
  3. 填写课程时长按全部课时的预计学习时间汇总。
  4. 点击“保存课程”系统先创建草稿，随后进入课程详情继续配置内容。

4. 列表页按钮和操作

刷新

重新读取课程列表。其他管理员刚完成操作，或状态未及时更新时使用。

从 JSON 创建课程

把符合课程导入格式的 JSON 创建为新课程。适合复制既有课程结构后再调整。

新建课程

从空白草稿开始创建一门新课程。

查看详情

查看课程完整字段和可复制的课程 JSON，不直接修改数据。

编辑

进入课程详情，维护基础信息、章节、课时、资料和测验。

克隆

创建同一课程的新草稿版本，沿用原 GPath 和内容。不要用它创建另一门独立课程。

“克隆”和“从 JSON 创建课程”的区别克隆用于同一门课程升级版本；从 JSON 创建用于创建另一门课程，导入前必须改成新的 course_gpath。

5. 维护课程内容

课程草稿创建后，按章节、课时、资料和测验逐层维护。先建立章节，再把课时和章节测验挂到正确章节。

章节与课时

对象作用配置要点
章节组织课程内容的一级目录。填写标题和排序；建议先创建全部章节，再逐一添加课时。
课时考生实际学习的内容单元。选择所属章节、标题、排序和课时类型，再填写正文或上传对应资源。

两类课程资料

类型考生端用途何时使用
候选端辅助资料显示在考生端“课程资料 / Supplementary Materials”列表。按章节提供文章、视频、PDF 或外部链接时使用。优先通过单条表单维护。
普通文件资料课程级文件资源。提供下载文件或课程附件时使用，不等同于候选端辅助资料列表。
辅助资料看不到时检查什么确认已创建辅助资料配置，并且 supplementary_material.data_json 中存在有效记录；外部链接需要填写完整的 https:// 地址。

测验题库

  1. 点击“加载测验”刷新当前课程下所有课程级、章节级和课时级测验。
  2. 点击“新测验”选择挂载层级和所属对象，填写测验标题及规则。
  3. 添加题目和选项设置题型、分值、必答、正确选项和排序。
  4. 复核挂载位置挂错层级会导致考生在错误的学习节点看到测验。

6. 使用 JSON 创建课程

适合以现有课程为模板快速创建结构相似的新课程。JSON 不是备份恢复文件，导入前仍需人工检查业务字段。

  1. 在源课程点击“查看详情”切换到“可导入 JSON”并点击“复制 JSON”。
  2. 修改新课程字段至少修改标题和 course_gpath；按需要调整描述、时长、章节、课时和测验。
  3. 点击“从 JSON 创建课程”上传 JSON 文件或直接粘贴内容。
  4. 等待导入完成系统会依次创建课程草稿、章节、课时和章节测验，并在最后校验数量。
  5. 进入草稿补充未覆盖配置逐项检查资料、测验和文件资源后再发布。
当前 JSON 的覆盖范围支持课程基础信息、章节、课时和章节测验。普通资料、辅助资料、课程测验及课时测验需要在新课程中另行配置。
导入失败后不要连续点击重试失败时页面会保留已经创建的草稿 ID。先进入该草稿确认已导入到哪一步，避免重复创建章节或测验。

7. 推荐的配置与发布顺序

创建草稿→基础信息→章节→课时→资料→测验→复核→发布

发布会使课程成为可被认证配置引用的正式版本。同一 GPath 发布新版本时，旧的当前版本会进入历史状态，因此发布前应确认认证配置准备切换到哪个课程版本。

不要直接在生产内容上试配置先在草稿完成全部编辑和预览，再发布。已经发布的课程如果需要大幅调整，应使用“克隆”创建新草稿版本。

8. 常见问题

新课程和新版本有什么区别？

新课程是独立业务对象，必须使用新的 GPath；新版本是同一课程的升级，使用“克隆”创建并沿用原 GPath。

为什么 GPath 不能填中文或大写字母？

GPath 是跨服务使用的稳定技术标识。系统只接受以斜杠开头的小写字母、数字、连字符、下划线和分段斜杠。

改了课程标题，GPath 也要一起改吗？

通常不需要。标题是展示名称，GPath 是业务系列标识。课程已经创建后，不要因文案调整随意改变 GPath。

为什么认证配置里选不到刚创建的课程？

先确认课程是否已发布。认证配置只能绑定可用的已发布课程，草稿、已下架或不可用版本不会出现在选择列表中。

候选端为什么看不到课程资料？

先判断要展示的是“辅助资料”还是“普通文件资料”。候选端 Supplementary Materials 依赖辅助资料配置及其 data_json；普通文件不会自动出现在该列表。

JSON 导入后为什么有些资料或测验没有出现？

当前导入范围不包含普通资料、辅助资料、课程测验和课时测验。这些内容需要进入新草稿后另行配置。

9. 发布前检查清单

  • 课程标题和描述使用正式对外文案
  • GPath 与业务对象匹配且未误用其他课程路径
  • 课程时长已填写
  • 章节顺序正确且无空章节
  • 每个课时挂载到正确章节
  • 正文、文件或视频资源可正常打开
  • 辅助资料在候选端展示位置正确
  • 普通资料的文件名称和内容正确
  • 测验挂载层级正确
  • 题目分值、正确答案和排序已复核
  • JSON 创建的课程已补齐未导入内容
  • 确认发布的是目标课程版本

认证配置使用手册

面向认证运营人员，说明认证管线的阶段、课程单元、免考、资格条件、证书、报读限制和版本发布。

角色：认证运营难度：进阶更新：2026-08-25

1. 功能概览

“认证配置”把已发布课程组织成一条可报读的认证管线，并规定购买门槛、课程免考、结业审核、最终发证和跨管线互斥规则。课程内容和商品价格不在这里维护。

认证管线→阶段→课程单元→终审→最终证书
依赖关系先在“课程配置”发布课程，在“资格定义”和“证书模板配置”准备资格与 PDF 模板，再完成认证配置；认证发布后，商品才能引用并配置价格。

2. 先理解这些概念

认证 GPath / 资源路径

认证业务系列的稳定路径，也是跨服务识别管线的关键字段。同一认证的不同版本沿用它，不同认证必须使用不同路径。

认证 ID / ULID

某个具体认证版本的唯一 ID，由系统生成。商品和流水最终会关联到具体版本。

阶段

认证学习流程的分组，例如 L1、L2。阶段按排序依次展示，每个阶段至少包含一个课程单元。

课程单元

阶段中的学习和计费单位，绑定一门已发布课程，可附带考试、免考及单元证书规则。

对象新业务对象同一对象升级版本
GPath使用新的唯一 GPath沿用原 GPath
创建方式点击“新建认证”在原版本上点击“克隆版本”
结果形成独立认证系列形成同一认证的下一草稿版本
不要通过修改名称来区分不同认证名称只是展示文案。把另一条认证误用为相同 GPath，会被识别成同一认证的版本，影响发布切换、商品引用和互斥判断。

3. 新建认证与版本管理

字段是否必填填写说明
名称必填管理后台和考生端显示的正式认证名称。
描述选填说明认证目标、对象和学习范围，不填写内部备注。
分类提示必填用于列表分组和筛选，例如 CFtP、CFtA；同系列保持一致。
资源路径必填即认证 GPath。建议采用系统生成值并确认唯一，例如 /gcc/pipeline/core/cftp。
状态含义允许的主要操作
草稿尚未对外生效编辑基础信息和完整结构、删除、发布
已发布当前可供商品和考生流程使用查看、克隆新版本、下架
已下架历史归档版本只读查看，不再修改
发布新版本会切换当前版本同一 GPath 下的新草稿发布后，原当前版本会进入已下架状态。先确认商品和运营流程已准备使用新版本。

4. 配置阶段

阶段用来表达认证的学习顺序和业务层级。先建立阶段，再进入“课程单元”页签绑定课程。

  1. 点击“新阶段”按业务顺序创建 L1、L2 等阶段。
  2. 填写名称和排序排序建议使用 1、2、3 等清晰序号，避免重复。
  3. 为阶段添加课程单元每个阶段至少需要一个已绑定课程的单元，结构才能保存。
  4. 检查阶段汇总确认单元名称、课程、考试代码和免考状态与预期一致。

5. 配置课程单元、考试与免考

字段作用配置要点
所属阶段决定单元位于认证的哪个学习阶段调整后要保存结构；不要只依赖左侧列表位置判断。
名称单元对外显示名称可与课程名一致，也可使用认证体系内的正式单元名。
排序决定同一阶段内的顺序同阶段保持唯一且连续。
关联课程指定实际学习内容只能选择已发布且可绑定的课程；绑定的是具体课程版本。
Program / Exam Code / Form Code对接考试项目、考试和试卷仅在该单元涉及考试时按考试系统约定填写。

免考规则怎么配

  1. 勾选“允许免考”未勾选时，即使考生持有相关资格，后台也不会自动免除该单元。
  2. 勾选一项或多项豁免资格考生持有其中任一有效资格即可满足该单元免考条件。
  3. 保存认证结构商品下单时，GMALL 会自动识别考生已持资格，应用免考并计算减免后的金额。
考生端不需要重复勾选自动免考项系统会把自动识别的免考与考生手工补充的其他免考去重合并；如果某阶段全部单元都被免考，该阶段实例化后会自动完成。
单元证书不是最终认证证书“单元完成后签发的资格 / 单元证书 PDF 模板”只在完成该单元就要单独发证时填写。认证全部完成后的主证书，应配置在“最终颁发证书”。

6. 区分三类资格与证书

配置层级检查时机业务含义典型示例

发证前终审材料全部课程完成后、发证前需要提交并通过审核的资格或材料工作经验证明、从业年限证明
最终颁发证书通关并通过终审后系统最终签发的资格和 PDF 证书CFtP Certification
不要混用字段前置准入和终审材料只保存资格要求，不包含 PDF 模板；最终颁发证书才同时包含资格定义和证书 PDF 模板。

7. 配置禁止报读和互斥管线

规则判断对象触发条件配置方向
禁止报读资格考生已持有的有效资格持有任一所选资格即禁止购买当前认证只配置在需要被禁止购买的一侧
互斥认证管线另一认证的进行中状态存在待支付订单或学习中实例时禁止购买当前认证两条认证必须分别配置对方 GPath
两种规则不能互相替代互斥处理“正在同时报读”的冲突；禁止报读处理“已经获得某资格后不能反向购买”。完成状态和进行中状态必须分别按业务规则配置。

8. CFTA / CFTP 推荐配置示例

下面按“允许没有 CFTA 的考生直接购买 CFTP；已有 CFTA 的考生自动免除 CFTP 中的 CFTA 课程；两条管线进行中不能同时购买；取得 CFTP 后不能反向购买 CFTA”的业务规则配置。

9. 保存、复核与发布

创建草稿→阶段→课程单元→资格与证书→报读限制→保存结构→发布
  1. 先保存基础信息确认名称、分类、描述和 GPath。
  2. 完成全部结构层级每次调整后点击“保存结构”，页面中的临时修改才会写入后台。
  3. 使用“完整结构 JSON”复核高级编辑区适合检查底层结构；“应用到分层视图”只更新页面状态，仍需再次保存结构。
  4. 发布前做跨模块检查确认课程已发布、资格定义可用、PDF 模板正确、商品准备绑定新版本。
  5. 点击发布并回归购买流程用无资格、持初阶资格、持高阶资格和存在进行中订单的测试账号分别预检。
已发布或已下架结构不可直接编辑需要调整时使用“克隆版本”，在新草稿完成修改和验证后再发布。不要通过下架当前版本来代替版本升级。

10. 常见问题

为什么课程单元里选不到刚创建的课程？

课程单元只显示可绑定的已发布课程。先到课程配置确认目标版本已发布，草稿、已下架或未启用课程不能绑定。

没有 CFTA 的考生也要能购买 CFTP，是否应该删除 CFTA 前置资格？

是。前置准入资格表示购买前必须持有。允许直接购买时应留空，并把 CFTA 课程加入 CFTP；已有 CFTA 的考生通过该单元的免考规则自动减免。

配置了豁免资格，为什么没有自动免考？

同时检查该课程单元是否勾选“允许免考”、豁免资格是否选择正确、考生持有的资格是否有效，以及认证结构是否已保存并随当前版本发布。

为什么 CFTA 和 CFTP 互斥只在一个方向生效？

互斥关系不是自动双向的。需要在 CFTA 中配置 CFTP GPath，同时在 CFTP 中配置 CFTA GPath。

禁止报读资格与前置准入资格有什么区别？

前置准入是“必须持有才可以买”；禁止报读是“持有任一项就不能买”。两者方向相反，不能配置成同一个业务含义。

最终颁发证书只选资格定义可以吗？

不可以。最终证书必须同时选择资格定义和证书 PDF 模板，否则发布前结构校验会失败，或后续无法正确生成证书。

11. 发布前检查清单

  • 认证名称、描述和分类提示为正式文案
  • GPath 属于正确认证系列且未误用其他管线路径
  • 每个阶段名称、排序正确
  • 每个阶段至少有一个课程单元
  • 所有单元绑定正确的已发布课程版本
  • 考试 Program、Exam Code、Form Code 已核对
  • 需要免考的单元已勾选“允许免考”
  • 豁免资格与单元业务规则一致
  • 前置准入资格没有误当作免考条件
  • 终审材料对应正确的资格定义
  • 最终证书同时配置资格和 PDF 模板
  • 禁止报读资格方向正确
  • 互斥管线已在两侧分别配置
  • 全部修改已点击“保存结构”
  • 已用不同资格状态的测试账号完成购买预检
  • 确认发布的是目标 GPath 的目标版本
