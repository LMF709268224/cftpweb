# Admin 用户管理反馈（2/3）

2026-11-24：按客户截图补充用户列与操作入口。与[用户管理 1/3](user-management-1.md)及[Dashboard](dashboard.md)一起汇总；本轮未部署。后续矩阵见 [3/3](user-management-3.md)，缺数据处理的修正见[禁止保底方案复查](no-fallback-review.md)。

## 已完成

1. 员工和考生列表、个人详情增加“最近登录”，显示日期及时间，支持中英文。数据取 Casdoor `LastSigninTime`；明确返回空字符串显示“暂无登录记录”，缺少字段显示不可获取，不拿创建时间替代，也不据此认定账号从未登录。
2. 员工列表增加 MFA 列，展示“已启用／未启用”；邮箱验证保留在员工详情，考生列表继续展示邮箱验证。BFF 只返回 `mfa_enabled`，判断与本地 Casdoor `User.IsMfaEnabled()` 一致，即 `PreferredMfaType != ""`，不向浏览器返回密钥或恢复码。前端遇到字段缺失显示不可获取，不误报“未启用”。
3. 桌面和手机的行操作改为“…”展开入口：两组都能查看详情；已关联考生身份的学员可查看课程报读。展开后可用键盘操作，Escape 收起；弹窗关闭后恢复焦点。缺失接口的动作不放假按钮。
4. 沿用上一页已完成的员工／考生分组、独立会员等级、认证报名详情、课程报读分页，不重复同一个账号。

## 暂缓：需要业务定义或权限约定

| 客户要求 | 当前依据／缺口 | 下一步 |
| --- | --- | --- |
| 员工 Role：Ops / Finance / Admin / Super Admin | 当前系统按配置的管理员角色识别员工，列表只显示现有用户类型，没有这四种岗位到 Casdoor 角色的明确映射；3/3 已补矩阵草案 | 确认矩阵差异与角色映射，见 [3/3](user-management-3.md)；不能把带 admin 字样的角色都当作 Super Admin |
| 员工 Status：Active / Suspended / Offboarded | 当前能识别启用、禁用、删除；禁用和删除不等同于离职 | 明确离职是否撤销所有会话、角色和资源访问，是否保留报名、订单、审计记录；需要独立状态或明确映射 |
| 考生 Candidate：Lead / L0 / L1 / L2 / Certified | 现有认证流程有自己的阶段、状态，一人可以有多次报名；无统一人员阶段 | 明确 Lead 定义、阶段配置映射、Certified 条件及多认证取值规则，再由服务端输出统一阶段。当前保留用户类型列，不伪造阶段 |
| Enrolments 数量（如 3 courses） | 现有 LMS 接口能分页查询报名，只有 `enrollments / has_more / next_cursor`，没有总数；认证报名和课程报读是不同实体 | 确认统计课程数还是报名次数，是否包含完成／撤销记录；建议按一组考生批量返回准确计数。当前已有查看明细，不能把首屏条数当总数 |
| Membership：None / Affiliate / Charterholder / Expired | 当前按实际有效记录及日期展示等级；缺少会员字段显示不可获取；历史接口已存在，但不能从当前 active 接口缺字段推出“从未加入”或“已到期” | 明确无记录的输出及已撤销、未生效、历史过期后又续费等状态的展示优先级；可基于历史实现，列表建议由会员服务提供汇总，避免逐人扫描全部历史 |
| Manage membership | BFF 已有授予／撤销会员接口及审计登记；现有 `/memberships` 页面管理的是方案配置，不是某个用户的会员资格 | 明确菜单需要授予、续期、升级、撤销中的哪些动作，以及有效期、理由、费用及管理员权限。不能链接到方案配置页冒充个人会员管理 |
| Checkbox / Bulk selection | 截图定义了勾选框，但未定义这页的批量动作、范围及失败处理 | 与 1/3 的批量待办合并；待动作确定后一起添加选择框，不提供无法操作的勾选状态 |

## 暂缓：账号管理接入缺口

以下不是新增一个前端按钮即可完成。当前 Admin BFF 的 `/api/user/profile`、`/api/user/password` 只操作登录管理员本人，没有面向指定用户的这些管理接口。可接 Casdoor 能力，但需 BFF 封装、服务端权限、身份校验及审计；不一定需要业务微服务新建接口。

| 菜单动作 | 适用对象 | 还需要什么 |
| --- | --- | --- |
| Edit role | 员工 | 角色映射、可分配范围及防止越权／锁死管理员的规则 |
| Reset password | 员工、考生 | 指定账号的重置协议；确认采用重置链接还是临时密码及首次登录要求，不复用修改本人密码接口 |
| Force logout | 员工 | Casdoor 会话／令牌撤销接入；核对当前 BFF 本地 JWT 验证是否即时感知撤销，明确单设备还是全部设备 |
| Reset MFA | 员工 | 管理员重置接口及权限，确认重置后的重新绑定要求 |
| Suspend / Reactivate | 员工、考生 | 指定账号的启停接口，明确已有会话与报名、会员状态的影响；不能只改列表颜色 |
| Offboard | 员工 | 按上表确认离职流程后接入，不使用删除账号代替 |
| Resend verification | 考生 | 服务端发送接口、未验证条件、频率限制及发送结果；不能把 `email_verified` 直接改成 true |
| Delete account | 考生 | 明确软删／硬删及订单、报名、会员、证书等关联记录处理；需要权限、确认和审计 |

## 数据与验证注意事项

- 最近登录是 Casdoor 账号的最近登录，不是“最近访问 Admin／最近学习”。数据沿用当前账号缓存及其刷新机制；不能据此生成学习活跃度统计。
- 本轮没有修改角色、账号启停、会员授予或认证状态规则；新增展示与行操作入口均不发送业务写请求。
- 本轮验收覆盖中英文、桌面／手机、两个用户分组、MFA 字段缺失、无登录记录、操作展开／键盘焦点、现有详情／报名分页回归，以及 BFF 不输出 MFA 密钥。
