## 2026-11-26 简版 Dashboard（待发布）

- 用户确认：收款不扣退款；按 UTC 零点统计今日收款，趋势取最近 24 小时与此前 24 小时的已完成订单金额对比。不同币种分别显示，不跨币种相加。订单仍最多扫描最近 500 条；截断时今日金额保留抽样提示、48 小时趋势不展示为准确对比。
- 收款数据当前调用 gpay 的 `/gpay.PayService/ListOrders`：请求只带 `status_filter=ORDER_STATUS_COMPLETED`、倒序游标和每页 100 条；响应的 `OrderSummary` 有 `paid_at`（Unix 秒）、`amount`（最小货币单位）和 `currency`。`OrderAdminFilters` 目前没有支付时间范围，BFF 最多扫描 500 条。最小接口改动是在 `ListOrders` 增加可选的 `paid_at` 起止时间过滤（UTC Unix 秒，起点包含、终点不包含），由服务端先过滤再分页；现有已完成订单状态过滤继续生效。接口上线后，BFF 需请求所需时间范围、读取全部分页，并按 `currency` 汇总金额和订单数，才能取消当前 500 条扫描上限。服务端直接返回汇总是可选的性能优化，不是完成此需求的前提；退款按本轮口径不扣减。
- 新增简版考生漏斗：按人去重统计“考生账号 → 有认证流程记录 → 已完成认证流程”。第一步来自 Casdoor 考生角色，后两步只计入能关联到这些账号的 gprog 流程记录；不把阶段 ID 映射成 Lead/L0/L1/L2，也不宣称流程完成等于证书颁发。流程记录扫描上限 500 条；截断或账号未关联业务 ID 时，后两步只显示下限，不计算转化率。
- 业务概览补充 UTC 近 48 小时新建考生账号和邮箱未验证的考生数，保留现有邮件状态入口。账号创建时间缺失时，新建人数显示不可获取，不补零。
- 用户确认最终口径：只扫描当前状态为 `Pending` 的申请，按申请创建时间统计是否已超过 48 小时；不单独处理重新提交时间。扫描上限 500 条时显示已统计数量的下限，不把它当作全量数。
