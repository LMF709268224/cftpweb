# Admin Dashboard 后续统计需求

2026-11-24：本次先接入现有接口能够明确提供的数据，不修改微服务或统计口径。此清单与[用户管理反馈](user-management-1.md)统一收录在[Admin 反馈目录](README.md)。

## 本次完成

- 当前页面已没有 Profile Completion，无需再移除。
- 顶部关键指标显示今日收款和待审核申请，可进入订单管理、审核中心。用户计数归入用户管理；后续用户管理调整后，当前显示员工与考生分组计数，点击分组查看对应列表。
- 今日收款沿用 `/api/dashboard/ops`。超过扫描上限时保留提示，不增加未经计算的增长百分比。
- 待审核申请使用 `/api/applications?status=Pending&page_size=1&include_status_subtotals=false` 返回的 `total`、`total_label`、`total_exact`，不拿当前页条数冒充总数。非精确计数保留 `+` 和说明。
- 业务概览显示 `/api/mails/stats` 的全部历史邮件当前发送状态，发送失败记录高亮，点击进入邮件列表并筛选相应状态。这里不重复显示待审核申请。
- 新文案支持中英文。接口失败显示不可获取，不显示为零。邮件接口成功返回空对象时，按 protobuf 空 map 的 JSON 省略规则显示零。
- 账号启用状态不等于业务活跃状态，会员角色数也不等于有效付费会员数。后续用户管理调整已去掉原角色计数卡，会员等级改为读取会员接口，详见用户管理清单。

## 暂缓项与所需接口

| 指标 | 现有能力 / 缺口 | 后续需要 |
| --- | --- | --- |
| 今日收入较昨日变化、趋势 | admin BFF 扫描最近最多 500 笔完成订单计算今日金额；不是完整的跨日期聚合 | 支付服务按支付时间、币种、指定时区汇总金额和订单数，返回当前与对比期间；确认收入是否扣除退款 |
| 新注册人数及日变化 | Casdoor 用户有创建时间，但尚无统一的新注册统计范围和时间口径 | 确认仅候选人还是包含管理员、采用哪个时区；账号侧或 BFF 按确定口径统计，未必需要新微服务 |
| 超过 48 小时的待审核申请 | 资格服务支持按 Pending 计数，筛选不支持时间范围 | 资格服务提供待审核总数和超时数；确认超过 48 小时从首次提交、最近重新提交还是进入 Pending 起算 |
| 有效会员、30 天内到期会员、本周变化 | 当前会员角色不表示付费有效期；会员查询以单个 candidate 为范围 | 会员服务提供全局有效会员人数、未来 30 天到期人数和对比期间，明确按用户去重及有效期规则 |
| 本月证书颁发、上月对比、撤销数 | 资格记录包含证书以外的资格，不能直接把全部 Credential 当成证书 | 明确纳入统计的证书类型，资格/证书服务按实际颁发和撤销事件统计，支持日期范围 |
| 今日发送邮件、投递率、最近 1 天失败数 | 邮件 stats 只有全部历史记录的当前发送状态； SENT 不等于已投递 | 邮件服务提供时间范围聚合、发送/投递/失败事件数量，并明确投递率分母和“1 天”的时间窗口 |
| Candidate Funnel、流失、转化率 | 当前 stage_id 是流程实例 ID；现有计数按认证记录且最多扫描 500 条，不是按唯一考生统计 | 先确认 Lead 定义、L0/L1/L2/Chartered 映射、多认证考生如何归类、流失及转化的时间范围和分母；进度服务按约定提供全量聚合 |

本次保留原阶段分布，未把技术阶段或状态强行映射为客户漏斗，未新增 Lead、流失率、转化率或推测的趋势数据。
