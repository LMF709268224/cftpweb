# Admin 用户管理反馈（1/3）

2026-11-24：优先完成现有接口支持、含义明确的展示和只读查询。此清单与[Dashboard 反馈](dashboard.md)统一收录在[Admin 反馈目录](README.md)。后续 [2/3 清单](user-management-2.md)补充了具体单人操作、账号状态、人员阶段与统计缺口，汇总时合并同类项。

## 已完成

1. 用户管理默认进入“学员／考生”，与“内部员工”分开；去掉混合账号入口和把会员作为角色筛选的入口，统一用户类型和账号状态文案。
2. 同一账号按 Casdoor 用户 ID 去重后再计数、筛选和分页。考生同时具有会员角色不会出现两行；不按姓名或邮箱合并不同账号。
3. 考生列表增加独立会员等级列。查询当前页考生的 `/api/memberships/active?candidate_ulid=...`，使用返回的 `membership_ulid` 获取目标语言翻译，不从 Casdoor 角色推测等级。限制并发为 4，共用相同方案的查询，翻页或切换语言时取消旧请求。
4. 会员接口当前只过滤 `status = active`，本次额外核对 `started_at`、`expires_at` 的展示有效期。实际记录明确未生效／已到期显示“无有效会员”；接口错误、缺少会员字段、日期不完整显示不可获取；未关联考生身份单独提示。仅处理展示，不调整会员授权。
5. 个人详情显示会员等级、起止日期、独立认证报名记录；每条报名展示认证名称、编号、报名状态和时间，支持加载更多及按现有认证状态筛选。课程报读继续使用独立记录入口。
6. 中英文、桌面和手机均支持。用户管理新增调用均为 GET，不触发授权、撤销、发送通知等业务操作。前端继续拒绝不完整列表／分页响应；2026-11-25 已按真实服务契约补齐课程报读的空页／末页 JSON 输出，详见[复查清单](no-fallback-review.md)。

## 暂缓项

| 客户要求 | 当前情况 | 还需要什么 |
| --- | --- | --- |
| 用户列表按业务状态筛选 | 现有接口分别提供账号启用状态、单个考生认证报名状态、单个考生会员记录；没有跨系统的用户筛选接口。本次已支持个人详情按报名状态筛选 | 明确“业务状态”是认证阶段、报名状态、会员状态还是审核状态；一人多报名时按任一匹配还是最高阶段匹配。之后需要在服务端按全量用户筛选并分页，不能只过滤当前页 |
| 统一考生身份状态 | 一人可以有多次报名，目前展示各报名自己的状态 | 明确要显示的考生状态定义及多认证优先级，不能把账号 Enabled 当成认证进度 |
| 单人业务操作 | 2/3 截图已列出改角色、重置密码、强制退出、MFA 重置、启停、离职、会员管理、重发验证和删除账号；查看详情／课程报读已有入口 | 具体缺口见 [2/3 清单](user-management-2.md)。Casdoor 管理操作需要 BFF 封装、权限检查和审计，现有个人资料接口只修改当前管理员自己 |
| 批量操作 | 目前没有用户批量操作协议；没有约定选中当前页还是全部筛选结果 | 确认动作、选择范围、确认方式、部分失败处理、是否支持重试；服务端需要逐项权限检查、幂等和审计。不能把单条修改请求循环调用当作已定义的批量功能 |
| Permission matrix / 管理员 RBAC | 现有 `/permissions` 页面用于考生资格处理，并非管理员权限矩阵；3/3 已提供矩阵草案 | Finance 权限冲突、Partial 范围等问题见 [3/3 清单](user-management-3.md)；确认后由服务端实现并返回有效权限，前端据此显示入口 |
| RFQ、SOW 等合同约束 | 本轮仅提供截图，未提供所引用条款 | 提供相关条款后核对是否还要求其他管理或审计行为 |

## 接口注意事项

- `/api/memberships/active` 当前返回一个 active 记录，未提供“指定一组考生、按等级／有效期过滤并分页”的能力。本次够用来显示当前页；全量会员筛选仍需服务端支持。
- 方案名称只使用对应语言的实际翻译；未配置翻译或服务不可用时显示不可获取，已移除原始名称替代逻辑。
- 当前员工分组沿用系统已有管理员角色规则；如需把没有该角色的其他员工也归入内部员工，需要补充具体角色映射。
- 本次没有修改现有授权、资格审核、会员变更或认证推进规则。
