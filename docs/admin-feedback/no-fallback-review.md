# 前期 Admin 改动复查：禁止保底方案

2026-11-24。范围：Dashboard（`089bd82d`）、User Management 1/3（`46ea9075`）、2/3（`e0e35940`）及其直接使用的课程报读组件。用户要求：接口未返回的数据写入清单，不猜测、不补零、不填默认身份或状态、不拿其他字段／语言顶替。

## 已移除的处理

| 原处理 | 现在行为 |
| --- | --- |
| 邮件统计缺 `status_counts` 当空 map，缺某状态计数显示 0 | 缺 map 显示不可获取；部分状态有数据则展示真实数值，缺失状态显示不可获取；只有明确返回的 0 才显示 0 |
| 会员目标语言翻译缺失／失败时使用方案原始名称 | 只使用请求语言的翻译；缺失显示不可获取，移除为替代名称而发起的方案详情调用 |
| 当前会员响应缺少 `membership` 时显示无有效会员 | 缺字段显示不可获取；明确的 `membership: null` 或实际记录日期明确不在有效期内才可显示无有效会员 |
| 认证报名／课程报读响应缺列表或 `has_more` 当空列表、最后一页 | 显示加载失败并允许重试；加载更多失败保留已成功读取的行，不声称没有报名或没有下一页 |
| 课程进度缺失显示 0% | 显示不可获取；明确的 0 正常显示 0% |
| 用户总数缺失改取当前页长度，页码缺失使用请求页码 | 要求响应提供列表、总数、页码和页面大小；缺失则报加载失败，不构造分页信息 |
| 缺失阶段数量、订单数、分组计数按 0 累加或展示 | 只累计完整且合法的返回计数；缺数据显示不可获取或不展示该统计 |
| 缺最近登录字段当作无登录记录，缺邮箱验证字段当未验证 | 区分字段缺失与接口明确返回的空字符串／false；缺字段显示不可获取 |

MFA 没有使用密钥是否存在来猜测：当前 BFF 使用 Casdoor 已有的 `PreferredMfaType`，判断与该服务自身 `User.IsMfaEnabled()` 一致。前端缺少 `mfa_enabled` 时显示不可获取，不当作 false。

## 接口缺口：没有用前端默认值修补

以下依据本地 BFF 与其已锁定版本的 protobuf 生成代码检查得出，**不是生产接口抓包结果**。部分生成字段带 `omitempty`，BFF 直接编码时会省略零值、false、空集合或空对象。2026-11-25 再次核对服务契约，以下表格区分已修复的输出和仍缺失的业务数据；前端不补值。

| 接口／数据 | 缺口与影响 | 后续要提供什么 |
| --- | --- | --- |
| `GET /api/mails/stats` | 空 map 可被省略；单个状态键也可能没有返回，无法仅根据 HTTP 数据确认其计数 | 明确返回各状态的真实计数，包括确认为 0 的状态；统计失败与空数据应可区分 |
| `GET /api/memberships/active?candidate_ulid=...` | 已修复：服务成功返回的无记录结果显式输出 `membership: null`；整体响应缺失仍报错 | 按原值展示无会员；RPC 失败不变成无记录，不推断历史身份 |
| `GET /api/memberships/{id}/translations?locale=...` | 返回中可能没有目标语言名称 | 配置对应语言翻译；不使用原始名称或其他语言代替 |
| `GET /api/prog/pipelines` | **纠正此前判断**：BFF 已用独立 map 明确输出 `pipelines`、`has_more` 和游标，不能仅从 protobuf 的 `omitempty` 推断 HTTP 缺字段 | 保持既有显式输出，前端仍拒绝真正不完整的响应 |
| `GET /api/lms/enrollments` | 已修复：真实 repeated 列表和分页值显式编码，0% 进度按服务字段原值输出 | 没有新增总数或推算进度；缺响应／缺实体报错，前端仍拒绝缺字段 |
| `GET /api/lms/courses/{id}/complete` | 已修复：成功响应中的真实空章节／空课时数组及课时正文原值不再省略 | 缺课程树／课程／章节／课时实体仍报错，状态、ID、版本、顺序不补值 |
| Dashboard 用户页、统计项 | 缺总数、页码、精确性、数量等必要字段时，旧页面会推测 | 保持现有 BFF 明确输出的必要字段；不完整响应现在被拒绝或展示不可获取 |
| 最近登录、邮箱验证、MFA | 对应字段缺失不能推出未登录、未验证或未启用 | 使用真实接口值；若实际来源不能提供则继续列为缺口 |

上述已修复部分发生在 BFF 的 JSON 输出层，不是微服务没有这些值。只对已核实语义的字段显式序列化，未新增前端兼容分支，也未改变服务状态、持久化记录或计算口径。成功空响应与服务失败／缺实体分别测试；邮件缺状态键等未定义信息仍不补零。证据见[中文说明复核](chinese-notes-review.md)。

## 保留的正常处理

- `0`、`false`、空数组等在响应中明确存在且符合契约时照实展示。
- 加载状态、不可获取、未知状态和错误提示用于标明能力缺口，不代表业务结果。
- 输入框初值、分页请求大小、筛选器的“全部”是用户界面的查询设置，不是填补接口业务数据。
- 用户身份展示不当作权限来源；没有创建 Ops／Finance／Super Admin 或推测权限。
